# Kroy

Kroy — прототип мультисайтовой платформы для сборки небольших сайтов из переиспользуемых React-компонентов — **запчастей** (*parts*). Редактор работает как SSR-приложение на [Vyaz](https://github.com/ivengurcev/vyaz).

## Текущее состояние

- Vyaz собирает и обслуживает список страниц и редактор в `/admin` домена сайта.
- Генератор обнаруживает запчасти и строит поля редактора из JSDoc.
- Панель показывает страницы текущего сайта, позволяет создавать, изменять и удалять их; редактор загружает выбранную страницу из PostgreSQL, изменяет её структуру и свойства запчастей, показывает живой предпросмотр и сохраняет изменения по кнопке.
- Страница хранится как массив `{ part, props }`; временные `id` остаются только в состоянии редактора.
- PostgreSQL хранит сайты, домены и страницы; API изолирует страницы по домену запроса.
- `yarn site:build <slug>` формирует многостраничный статический сайт из PostgreSQL без клиентского JavaScript.

Пользователи, авторизация и автоматическая публикация пока не реализованы.

## Исходные каталоги

| Путь | Назначение |
|---|---|
| `editor/` | Интерфейс и состояние редактора |
| `api/` | Доменно-зависимые обработчики API |
| `db/` | Подключение, seed и миграции PostgreSQL |
| `layout/` | Общие компоненты рендеринга страницы |
| `parts/` | React-запчасти сайта |
| `demo/` | Исходные данные для первоначального заполнения локальной БД |
| `scripts/` | Обнаружение запчастей и статическая генерация |
| `server.mjs` | Конфигурация приложения Vyaz |

Все результаты сборки находятся в `dist/`:

| Путь | Назначение |
|---|---|
| `dist/public/` | Клиентская сборка Vyaz |
| `dist/ssr/` | Серверная сборка Vyaz |
| `dist/kroy/` | Реестры, метаданные и промежуточные файлы Kroy |
| `dist/sites/<site>/` | Готовые статические сайты |

## Запчасти

Запчасти обнаруживаются в `parts/`. JSDoc над `export default` описывает редактируемые свойства: обычные `@param` задают поля, а `@kroy` — виджеты и ограничения.

```jsx
/**
 * @param {object} props
 * @param {string} props.phone - Телефон
 * @kroy phone widget=tel format=ru
 */
export default function Contacts({ phone }) {
    return <a href={`tel:${phone}`}>{phone}</a>;
}
```

На основе описаний Kroy создаёт полный реестр для редактора и сокращённый реестр используемых запчастей для статического сайта.

Идентификаторы имеют вид `@kroy/<kebab-case>`. Имена, выведенные из путей, нормализуются автоматически: `GallerySimple.jsx` → `@kroy/gallery-simple`, `section/Main.jsx` → `@kroy/section/main`. Явное `name` из `package.json` имеет приоритет и должно соответствовать тому же формату.

## Запуск

```bash
yarn install
yarn vyaz:build
yarn vyaz:serve
```

После запуска Vyaz напрямую доступен на порту `3000`. При запущенном preview список страниц демонстрационного сайта открывается через единую точку входа `http://demo.localhost:8080/admin/pages`. Маршрут `/admin` по-прежнему открывает редактор главной страницы.

Заполнить локальную БД и собрать оба тестовых сайта:

```bash
yarn db:seed
yarn site:build demo
yarn site:build test
```

`yarn demo` остаётся коротким алиасом сборки `demo`. Главная страница записывается в `dist/sites/<slug>/index.html`, а вложенные пути — например, в `dist/sites/<slug>/about/team/index.html`. Перед сборкой очищается только каталог выбранного сайта, поэтому сборка `test` не меняет HTML и правила `demo`. Домены берутся из таблицы `domains`, а общая проверенная конфигурация записывается в `dist/kroy/caddy/Caddyfile`.

Создать новый локальный сайт с пустой главной страницей и собрать его:

```bash
yarn site:create vet vet.localhost "Семейный ветеринар"
yarn site:build vet
yarn preview:reload
```

Название необязательно и по умолчанию равно slug. Команда создания отклоняет занятые slug и домены и не изменяет существующие данные.

Посмотреть список сайтов или подробную информацию об одном сайте:

```bash
yarn site:list
yarn site:info demo
```

Добавить или удалить дополнительный локальный домен сайта:

```bash
yarn site:domain:add demo second-demo.localhost
yarn site:build demo
yarn preview:reload

yarn site:domain:remove demo second-demo.localhost
yarn site:build demo
yarn preview:reload
```

Последний домен сайта удалить нельзя. После изменения доменов нужно пересобрать сайт и перезагрузить Caddy, чтобы обновить preview-конфигурацию.

Локальный просмотр готового сайта через Caddy:

```bash
yarn preview
```

Сайты доступны одновременно на `http://demo.localhost:8080` и `http://test.localhost:8080`. После повторной сборки сайта применить обновлённые правила без пересоздания контейнера:

```bash
yarn preview:reload
```

Caddy раздаёт каталог каждого сайта только на связанных с ним доменах, применяет его правила `301`/`410` и проксирует `/admin`, `/api`, `/public`, `/static` и `/uploads` в общий Vyaz на порту `3000`. Неизвестный Host получает `404`. При сборке общий Caddyfile проверяется командой `caddy validate` до замены рабочей конфигурации. Отдельная проверка текущего файла запускается командой `yarn preview:validate`.

Публичные пути используют только нижний регистр, цифры и дефисы в непустых сегментах: `/`, `/services`, `/about/team`, `/our-services`. Проценты, URL-кодировки, пробелы, точки и метасимволы не допускаются, чтобы PostgreSQL, браузер, файловая система и Caddy однозначно трактовали адрес. Первые сегменты `admin`, `api`, `public`, `static` и `uploads` зарезервированы для приложения.

## Локальная база данных

Создайте локальный файл окружения и запустите PostgreSQL:

```bash
cp .env.example .env
docker compose up -d db
```

Управление миграциями:

```bash
docker compose run --rm migrate up
docker compose run --rm migrate status
docker compose run --rm migrate rollback
yarn db:seed
```

PostgreSQL доступен только локально на `127.0.0.1:5433`. Сервис `migrate` запускается только явной командой; dbmate не создаёт `db/schema.sql`.

API страниц определяет сайт только по заголовку `Host` и таблице `domains`:

```text
GET /api/pages
GET /api/pages?deleted=1
POST /api/pages
GET /api/pages?path=/
GET /api/pages/:pageId
PATCH /api/pages/:pageId
PUT /api/pages/:pageId
DELETE /api/pages/:pageId
POST /api/pages/:pageId/restore
```

Для демонстрационного сайта используйте `http://demo.localhost:8080/api/pages`; Caddy сохраняет исходный `Host`, по которому API определяет сайт.

Удаление страницы является мягким: запись и содержимое сохраняются в PostgreSQL, а занятый путь нельзя использовать повторно. Главную страницу удалить нельзя. Удалённые страницы доступны в `/admin/pages/trash` и могут быть восстановлены.

При изменении публичного пути прежний адрес сохраняется в `redirects` со ссылкой на UUID страницы. Создание страниц и изменение путей выполняются транзакционно; зарезервированный редиректом адрес нельзя занять другой страницей. Статическая сборка формирует правила `301` и `410`, а локальный Caddy применяет их в preview.

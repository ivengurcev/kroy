# Kroy

Kroy — прототип мультисайтовой платформы для сборки небольших сайтов из переиспользуемых React-компонентов — **запчастей** (*parts*). Редактор работает как SSR-приложение на [Vyaz](https://github.com/ivengurcev/vyaz).

## Текущее состояние

- Vyaz собирает и обслуживает список страниц и редактор в `/admin` домена сайта.
- Генератор обнаруживает запчасти и строит поля редактора из JSDoc.
- Панель показывает страницы текущего сайта, позволяет создавать, изменять и удалять их; редактор загружает выбранную страницу из PostgreSQL, изменяет её структуру и свойства запчастей, показывает живой предпросмотр и сохраняет изменения по кнопке.
- Страница хранится как массив `{ part, props }`; временные `id` остаются только в состоянии редактора.
- PostgreSQL хранит сайты, домены и страницы; API изолирует страницы по домену запроса.
- `yarn demo` формирует статический HTML тестового сайта без клиентского JavaScript.

Пользователи, авторизация и автоматическая публикация пока не реализованы.

## Исходные каталоги

| Путь | Назначение |
|---|---|
| `editor/` | Интерфейс и состояние редактора |
| `api/` | Доменно-зависимые обработчики API |
| `db/` | Подключение, seed и миграции PostgreSQL |
| `layout/` | Общие компоненты рендеринга страницы |
| `parts/` | React-запчасти сайта |
| `demo/` | Тестовый JSON страницы |
| `scripts/` | Обнаружение запчастей и статическая генерация |
| `server.mjs` | Конфигурация приложения Vyaz |

Все результаты сборки находятся в `dist/`:

| Путь | Назначение |
|---|---|
| `dist/public/` | Клиентская сборка Vyaz |
| `dist/ssr/` | Серверная сборка Vyaz |
| `dist/kroy/` | Реестры, метаданные и промежуточные файлы Kroy |
| `dist/sites/<site>/` | Готовые статические сайты |

## Запчасти

Запчасти обнаруживаются в `parts/`. JSDoc над `export default` описывает редактируемые свойства: обычные `@param` задают поля, а `@kroy` — виджеты и ограничения.

```jsx
/**
 * @param {object} props
 * @param {string} props.phone - Телефон
 * @kroy phone widget=tel format=ru
 */
export default function Contacts({ phone }) {
    return <a href={`tel:${phone}`}>{phone}</a>;
}
```

На основе описаний Kroy создаёт полный реестр для редактора и сокращённый реестр используемых запчастей для статического сайта.

Идентификаторы имеют вид `@kroy/<kebab-case>`. Имена, выведенные из путей, нормализуются автоматически: `GallerySimple.jsx` → `@kroy/gallery-simple`, `section/Main.jsx` → `@kroy/section/main`. Явное `name` из `package.json` имеет приоритет и должно соответствовать тому же формату.

## Запуск

```bash
yarn install
yarn vyaz:build
yarn vyaz:serve
```

После запуска список страниц демонстрационного сайта доступен по адресу `http://demo.localhost:3000/admin/pages`. Маршрут `/admin` по-прежнему открывает редактор главной страницы.

Сгенерировать статический demo-сайт:

```bash
yarn demo
```

Результат: `dist/sites/demo/index.html`.

## Локальная база данных

Создайте локальный файл окружения и запустите PostgreSQL:

```bash
cp .env.example .env
docker compose up -d db
```

Управление миграциями:

```bash
docker compose run --rm migrate up
docker compose run --rm migrate status
docker compose run --rm migrate rollback
yarn db:seed
```

PostgreSQL доступен только локально на `127.0.0.1:5433`. Сервис `migrate` запускается только явной командой; dbmate не создаёт `db/schema.sql`.

API страниц определяет сайт только по заголовку `Host` и таблице `domains`:

```text
GET /api/pages
GET /api/pages?deleted=1
POST /api/pages
GET /api/pages?path=/
GET /api/pages/:pageId
PATCH /api/pages/:pageId
PUT /api/pages/:pageId
DELETE /api/pages/:pageId
POST /api/pages/:pageId/restore
```

Для демонстрационного сайта используйте `Host: demo.localhost:3000`.

Удаление страницы является мягким: запись и содержимое сохраняются в PostgreSQL, а занятый путь нельзя использовать повторно. Главную страницу удалить нельзя. Удалённые страницы доступны в `/admin/pages/trash` и могут быть восстановлены.

При изменении публичного пути прежний адрес сохраняется в `redirects` со ссылкой на UUID страницы. Создание страниц и изменение путей выполняются транзакционно; зарезервированный редиректом адрес нельзя занять другой страницей. HTTP-ответы `301` и `410` пока не реализованы.

# AGENTS.md

Kroy / Oysite — мультисайтовая платформа на JavaScript, React 19, Vyaz,
esbuild, PostgreSQL и Yarn 4 PnP. Приложение настраивается в `server.mjs`; административный интерфейс находится в
`admin/`; публичный сайт находится в `site/`: `site/parts/` готовят данные,
`site/widgets/` отображают их, `site/runtime/` рендерит страницы.

## Документация перед изменениями

Прочитать относящиеся к задаче документы до изменения подсистемы:

- [requirements.md](docs/requirements.md) — бизнес-поведение, роли и границы MVP.
- [arch-rules.md](docs/arch-rules.md) — обязательные архитектурные ограничения.
- [architecture.md](docs/architecture.md) — устройство системы и принятые решения.
- [PARTS.md](docs/PARTS.md), [EDITOR.md](docs/EDITOR.md),
  [ROUTING.md](docs/ROUTING.md), [prodamus.md](docs/prodamus.md) — контракты подсистем.
- [infra/README.md](infra/README.md) и [Ansible](infra/ansible/README.md) — эксплуатация.

Сохранять принятые требования и ограничения. Если согласованная задача меняет
требование — обновить requirements.md; архитектурное ограничение — arch-rules.md;
принятое архитектурное решение — architecture.md. Обновлять профильную справку,
если меняются публичный контракт или существенное поведение подсистемы.
Не переписывать документацию из-за мелких стилей, формулировок и несвязанных правок.
Не разрешать самостоятельно спорные продуктовые вопросы.

[docs/superpowers/](docs/superpowers/README.md) — исторические планы и спецификации,
не текущие инструкции. При конфликте с принятыми решениями не следовать им;
невыполненный пункт плана сам по себе не создаёт новое требование.

## Правила работы

- Минимальные изменения строго в рамках задачи; не менять соседний код и форматирование.
- Не добавлять абстракции и зависимости без необходимости; сохранять JavaScript.
- Не заниматься сборкой сайтов и динамическими импортами без отдельного запроса.
- Блок content: `{ part, props, view: { name, props } }`; совместимый `view` обязателен.
  Временный `id` — только состояние редактора, в JSON не сохраняется.
- JSDoc исходников — источник метаданных полей. `dist/` не редактировать:
  `dist/public/`, `dist/ssr/` — Vyaz; `dist/kroy/` — реестры/staging;
  `dist/sites/<site>/<release-id>/` — опубликованные релизы.
- Директории — `kebab-case`, React-компоненты — `PascalCase`, обычные JS-модули —
  `camelCase`. Идентификаторы запчастей и виджетов — `@kroy/` с сегментами в kebab-case.

## Git и проверка

- Git status, diff, историю, сообщения и создание коммитов делегировать `git-manager`.
- Коммит только по явному запросу пользователя; автоматически не коммитить и не push.
  По запросу сообщения предложить три варианта Conventional Commit без коммита.
- После реализации выполнить `git diff --check` через `git-manager` и одну профильную
  сборку, если окружение готово. Для изменений только документации проверить ссылки;
  сборки и тесты не запускать, если не нужны документационному инструменту.
- Не запускать браузер, headless Chrome, E2E и дополнительные проверки сценариев.
  Не создавать тесты или тестовую инфраструктуру без отдельного запроса.
- Минимизировать затраты проверок; не повторять их без конкретной причины.

Пользователь проверяет функциональность в браузере самостоятельно. Итог кратко:
что изменено, результат технической проверки и что проверить вручную.

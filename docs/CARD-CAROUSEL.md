# Oysite: универсальная карусель карточек

**Статус: реализовано.** Компонент и виджеты находятся в `site/components/`,
`site/widgets/material-carousel/` и `site/widgets/review-carousel/`; профильные
unit-, компонентные и SSR-проверки — `site/components/*.test.mjs` и
`site/runtime/carouselWidgets.test.mjs`. Production-поведение ниже остаётся
контрактом.

## 1. Цель и область применения

`CardCarousel` размещает готовые React-карточки в один ряд и управляет горизонтальным
перелистыванием. Виджет определяет разметку и оформление карточек, заголовок секции,
состояние пустого списка и дополнительные действия. Компонент не загружает данные
и не знает о материалах, отзывах, преимуществах или товарах.

Первая версия: два новых альтернативных виджета для материалов и отзывов.
Преимущества и товары — возможные последующие применения. Автопрокрутка,
зацикливание, виртуализация и сторонние runtime-библиотеки не входят в объём.

## 2. Требования к поведению

- Карточки в одном ряду в исходном порядке, без переноса и дубликатов для прокрутки.
- В покое одновременно видны 1–4 целые карточки либо все карточки, если их меньше
  доступных мест. Короткий список начинается слева, карточки сохраняют ширину
  слота, свободное место остаётся справа. Частичная видимость допустима только
  во время движения.
- «Назад» и «Вперёд» сдвигают окно на одну карточку. На соответствующей границе
  кнопка недоступна; если список помещается, обе кнопки и счётчик скрыты.
- Свайп и трекпад используют нативную прокрутку. Инерционный жест может пройти
  несколько карточек, но всегда заканчивается на допустимой позиции.
  Нативная горизонтальная полоса прокрутки визуально скрыта.
- При заполненном ряде первое окно начинается у левого края, а последнее
  заканчивается у правого. Программные переходы плавные, при
  `prefers-reduced-motion: reduce` — мгновенные.
- При изменении ширины или данных позиция пересчитывается, а карточки с прежними
  ключами остаются смонтированными. Состояние карусели не сохраняется в `content`.

## 3. Адаптивная модель и геометрия

`W` — ширина области просмотра карусели **внутри** контейнера виджета, после его
внешних полей и ограничения `--site-container-max`. Кнопки находятся над областью
просмотра и не вычитаются из `W`. CSS container queries измеряют собственную
обёртку карусели, ширина content box которой равна ширине области просмотра.
У области просмотра нет горизонтальных рамок, padding и scroll-padding; у ряда
нет краевых отступов и внешних отступов карточек.

Ориентир для минимальной ширины при нескольких карточках — `280px`, как в
[сетке материалов](../site/widgets/material-cards/materialCards.module.css).
Промежуток `G` — `--site-space-6` (штатно `24px`, не настройка виджета).
Предлагаемые пороги выводятся из `K × 280 + (K − 1) × 24`:

| Ширина контейнера `W` | Доступные места `K` | Контрольные ширины `W` |
| --- | ---: | --- |
| Менее `584px` | 1 | 320, 375, 560 |
| От `584px` до `888px` (не включая) | 2 | 584, 768 |
| От `888px` до `1192px` (не включая) | 3 | 888, 1024 |
| `1192px` и выше | 4 | 1192, 1440 |

`280px` — ориентир для перехода к нескольким карточкам, а не CSS `min-width`:
если `W < 280px`, одна карточка всё равно должна поместиться. Пороги фиксированы
для штатного токена промежутка; формула ширины использует его фактическое значение.

Для `N > 0`, где `N` — число карточек:

```text
V = min(N, K)                         # видимых карточек
C = (W − (K − 1) × G) / K            # ширина стандартного слота
S = max(0, N − K)                     # последний допустимый старт
i = clamp(желаемая позиция, 0, S)      # индекс первой видимой карточки
```

При `N = 0` карусель не рендерится, `V = S = i = 0`. При `0 < N < K` ширина
ряда карточек — `N × C + (N − 1) × G`, свободное место справа —
`(K − N) × (C + G)`. Пустые элементы не добавляются, панель со счётчиком скрыта.
Например, при `W = 1440px`, `K = 4`, `G = 24px` ширина карточки — `342px`.
Одна карточка оставляет справа `1098px`, две карточки с промежутком —
`732px`; в обоих случаях `S = i = 0`.

При `N ≥ K` окно заполнено `K` карточками. Например, для шести карточек при
`W = 768px`: `K = V = 2`, `C = 372px`, `S = 4`; последнее окно содержит
карточки 5 и 6. Его смещение `(N − K) × (C + G)` равно ширине ряда минус `W`.
Последняя карточка доходит до правого края без проставок и неполного шага.
При `N = K` единственное окно тоже заполняет всю ширину, контролов нет.

CSS вычисляет ширину дробно, без округления каждой карточки. Для перехода JS меряет
начало целевой обёртки относительно scrollport и текущей позиции и ограничивает
цель фактическим диапазоном прокрутки. Умножение округлённой ширины на индекс
недопустимо: на длинном списке погрешность накопится.

## 4. Архитектура компонента

| Подход | Плюсы | Издержки |
| --- | --- | --- |
| Нативный `overflow-x: auto` + CSS `scroll-snap` | Свайп, инерция, трекпад и вертикальный скролл страницы остаются браузеру; CSS-раскладка и ручная прокрутка работают до гидратации | Нужно синхронизировать кнопки и фокус с фактической остановкой, перепроверять позицию при resize и учитывать различия движков |
| `transform: translateX()` | Прямой контроль индекса и анимации для переходов по кнопкам | Нужно отдельно реализовать жест, отмену, направление, порог, инерцию и клавиатурный доступ; до инициализации нет нативной прокрутки |

**Выбор: нативная прокрутка с `scroll-snap`.** Цепочка разметки: именованная
группа → панель управления и отдельная прокручиваемая область → список `ul/li`.
Список — flex-ряд без переноса, карточки не растут и не сжимаются относительно
вычисленной ширины. Snap — обязательный по горизонтали (`x mandatory`), выравнивание
по началу карточки. Если `N > K`, позиции начала карточек с индексами больше
`S` лежат вне диапазона: фактический конец прокрутки совпадает с началом
карточки `S`. При `N ≤ K` прокручивать нечего. После остановки компонент
сопоставляет смещение ближайшей допустимой позиции `0…S` и исправляет его
мгновенно, если оно отличается от этой позиции более чем на 1 CSS px.
Через `scrollIntoView()` не листать: это может переместить и страницу.

- **Один источник адаптивности.** CSS задаёт число слотов через custom property
  с container queries и вычисляет ширину карточки по числу слотов `K`.
  JS считывает тот же CSS-счётчик после первого измерения и при изменении размеров;
  копия таблицы порогов в runtime JS не нужна.
- **Скрытая полоса прокрутки.** На области просмотра задать `scrollbar-width: none`
  (Firefox и современные Chromium/WebKit) и скрыть `::-webkit-scrollbar` через
  `display: none` как резерв для Chromium/WebKit. Сохранить `overflow-x: auto`
  и scroll snap. Не блокировать стандартные жесты прокрутки, события колеса
  и нативную клавиатурную прокрутку; отдельный drag-механизм не нужен.
- **Позиция и команды.** Хранить подтверждённый старт и, только пока выполняется
  команда, целевой индекс. Повторное нажатие прибавляет один к текущей цели, чтобы
  два быстрых нажатия давали два шага. Нативный жест прерывает очередь цели;
  после него состояние берётся из измеренной позиции. Статус и доступность
  карточек обновляются по подтверждённой позиции, не на каждом `scroll`.
- **Завершение движения.** Использовать `scrollend`, где он поддерживается.
  Резерв — пассивный `scroll`, короткая пауза после последнего события и проверка,
  что позиция стабильна в двух кадрах и сенсорный жест уже отпущен. Команда без
  изменения позиции завершается сразу. Устаревшее завершение после resize,
  нового жеста или смены списка не должно перезаписывать новое состояние;
  слушатели, observer, таймер и кадры очищаются при размонтировании.
- **Resize и данные.** `ResizeObserver` следит за областью просмотра; измерения
  группируются в кадр, из callback не меняется её наблюдаемая ширина. При
  изменении ширины/списка отменить прежнюю цель, найти ключ первой карточки
  последнего подтверждённого окна в новом порядке и ограничить её индекс `0…S`.
  Если ключ удалён, ограничить прежний индекс. Выравнивание при пересчёте
  мгновенное. Без `ResizeObserver`: начальное измерение, `window.resize` и
  повторное измерение перед командами и при смене списка. CSS всё равно
  перестраивает ряд; в таком окружении синхронизация контролов после изменения
  только контейнера может ждать ближайшего события.
- **SSR.** Сервер и первый клиентский рендер выводят один и тот же список со всеми
  карточками. Во время рендера нет чтения DOM или медиаусловий из JS. До измерения
  JS-кнопок и `inert` нет, доступна нативная прокрутка, в том числе без JS.
  Область просмотра фокусируема, полоса визуально скрыта уже в SSR-раскладке.
  Hydration-эффект синхронизируется с текущей нативной позицией, в том числе если
  пользователь уже пролистал список.

## 5. Предлагаемый API

Публичный компонент — `site/components/CardCarousel.jsx`, стили — соседний
CSS Module. Минимальный вызов:

```jsx
<CardCarousel label="Материалы">
    {data.map((material) => (
        <MaterialCard key={material.slug} material={material} />
    ))}
</CardCarousel>
```

| Параметр | Контракт |
| --- | --- |
| `label` | Обязательное непустое доступное имя группы на языке интерфейса. Виджет берёт его из заголовка или использует смысловую подпись при отсутствии заголовка. |
| `children` | Массив готовых React-элементов: один корневой элемент на карточку, стабильный и уникальный `key` на каждом. Карточка не передаёт внешний `li`: список создаёт карусель. Пустой массив даёт `null`. |

Ключ элемента используется и для обёртки `li`, и как якорь при обновлениях;
компонент не клонирует карточки и не управляет их props. В первой версии нет
`renderItem`, управляемого индекса, callbacks, API размера, слотов навигации
или замены scroll-движка.

Полезный пример очистки observer и кадра, но его геометрия и лимит не переносятся. |

При реализации вынести только разметку карточек в разделяемые локальные компоненты
рядом с соответствующими карточными виджетами. Общие card-стили можно
переиспользовать из их CSS Modules; grid-раскладка, настройки `columns` и
существующие состояния остаются у сеток. Импорты направлять на модуль карточки,
не на точку входа сеточного виджета. Мозаика и старый слайдер не затрагиваются.

Материалы получаются из [`prepareMaterialList`](../site/parts/material-list/prepareMaterialList.mjs):
готовый массив `{ slug, title, summary, coverUrl, href }`, только опубликованные
записи нужного раздела, включая выбор `materialSectionId` в детальном шаблоне.
Отзывы — из [`prepareReviews`](../site/parts/reviews/prepareReviews.mjs):
готовый объект с `title`, отобранным `reviews` и флагами. Сохраняется порядок
из запчасти. Ключ — `review.id`; если в сохранённой ручной подборке ID повторяется,
ключ повторной карточки дополняется порядковым номером появления этого ID
(не индексом всего списка), чтобы не терять показанные записи и не дублировать ключи.
Загрузка, фильтрация и лимиты запчастей не меняются.

Регистрация через `package.json` с `name` и `main` в каждом новом каталоге и JSDoc
перед `export default`: `@kroy-title`, `@kroy-category`, `@kroy-contract`.
[`discoverParts.mjs`](../build/registry/discoverParts.mjs) подхватывает метаданные;
[`PartEditor`](../admin/editor/PartEditor.jsx) показывает варианты по совпадению
контракта. Default widgets остаются `@kroy/material-cards` и `@kroy/reviews-slider`.
Выбор карусели меняет только `view`; формат, миграции и существующие страницы не
требуют изменений. Публичный реестр по своему действующему правилу берёт только
используемые виджеты. См. [контракт запчастей](PARTS.md).

[`Page`](../site/runtime/Page.jsx) передаёт готовые данные и `view.props` через
штатный вызов виджета. Новые виджеты сохраняют один корневой
[`Section`](../site/runtime/Section.jsx), собственную внутреннюю обёртку и
стандартные `spacingTop`/`spacingBottom`. Карусель наследует токены из
[`SiteRoot`](../site/runtime/SiteRoot.jsx). Это работает в
[живом редакторе](../admin/editor/EditorWorkspace.jsx) (`SiteRoot` + `Page`)
и в [предпросмотре сохранённого сайта](../admin/pages/PreviewPage.jsx) (`SiteApp`).
Оба режима проверяются отдельно от публичной страницы.

**Настройка числа карточек:** в первой версии только автоматический расчёт.
На вкладке «Виджет» остаются выбор представления и общие отступы. Если появится
реальная потребность, обсуждать верхний предел (`maxVisible`) как настройку
представления, не как принудительное число карточек для любой ширины.

## 7. Доступность

- Именованная группа, список `ul/li`, нативные `<button type="button">` с
  `aria-label="Предыдущая карточка"` / `"Следующая карточка"` и `aria-controls`
  для уникального ID области просмотра. Иконки декоративные; цели нажатия
  не меньше `44 × 44px`, фокус виден в обеих палитрах.
- Кнопки до списка в DOM. Tab / Shift+Tab идут обычным порядком, Enter / Space
  активируют кнопки. На самой фокусируемой области просмотра Left / Right
  листают на одну карточку, Home / End — в начало / конец. Не перехватывать
  события из карточек (ссылки, кнопки, поля), с модификаторами или вне карусели;
  вертикальная прокрутка страницы и выход по Tab сохраняются.
- Пока есть переполнение, обе кнопки остаются на своих местах. На границе —
  `aria-disabled="true"` и блокировка действия в обработчике, чтобы кнопка
  не теряла фокус после последнего нажатия. Если переполнение исчезло, убрать
  панель; если фокус был на её кнопке, перевести его в область просмотра без
  прокрутки. Пока размер неизвестен или есть переполнение, область просмотра
  входит в Tab-порядок; при отсутствии переполнения она остаётся только
  программной целью фокуса (`tabIndex={-1}`). Не переводить фокус на карточку
  при каждом перелистывании.
- После измерения и в покое карточки вне подтверждённого окна получают `inert`
  на обёртке `li`: они остаются в DOM, но недоступны для Tab и ассистивных
  технологий. При завершении движения с фокусом в уходящей карточке сначала
  перевести его в область просмотра (`preventScroll`), затем применить `inert`.
  Если элемент по-прежнему виден, сохранить фокус. При удалении сфокусированной
  карточки перевести фокус в область просмотра, только если обновление оставило
  его без цели и пользователь уже не ушёл в другой блок. При `N = 0` и
  размонтировании всей области восстановление фокуса — ответственность виджета
  или редактора, если обновление действительно удалило элемент с фокусом.
- Видимый счётчик «Карточки 3–5 из 12» рядом с кнопками показывает наличие
  дополнительных карточек. Обновление подтверждённого диапазона сообщается через
  `aria-live="polite"` / `aria-atomic="true"` один раз после остановки, без
  озвучивания промежуточных смещений. При отсутствии переполнения счётчик скрыт.
- Без JS видимая подсказка перед областью просмотра объясняет, как увидеть
  остальные карточки: «Чтобы увидеть остальные карточки, прокрутите список
  вбок или перейдите в него клавишей Tab и используйте стрелки». Подсказка
  есть в серверном HTML; CSS показывает её только при переполнении, по тем же
  порогам контейнера и количеству карточек. После инициализации её заменяют
  кнопки и счётчик. Без JS Tab переводит фокус в именованную область просмотра,
  стрелки используют нативную горизонтальную прокрутку; ссылки во всех
  карточках остаются доступны через Tab. Свайп и трекпад работают в обоих режимах.
- `prefers-reduced-motion` применяется к каждому программному переходу
  (`instant` либо `auto` с CSS `scroll-behavior: auto` в этом режиме).
  Нативная механика прокрутки от пользовательского жеста остаётся браузеру.

## 8. Пограничные случаи и ограничения

- **Разная высота.** Обёртки в ряду выровнены сверху, без фиксированной высоты,
  обрезки текста и повторного измерения высот при каждом шаге. Высоту ряда
  задаёт самая высокая карточка из всего списка: под короткими карточками может
  остаться вертикальное пространство. Горизонтальная геометрия от высоты не зависит.
- **Узкая карточка и длинное содержимое.** Обёртки допускают `min-inline-size: 0`;
  в новых представлениях текстовые поля переносят длинные токены
  (`overflow-wrap: anywhere`), медиа не шире карточки. Фокусный контур внутри
  карточки не должен обрезаться scrollport. Ограничение ширины виджета и сам
  scrollport должны помещаться в родителе, включая flex/grid админки.
- **Скрытие и возврат.** Нулевая ширина скрытого контейнера не сбрасывает
  последнюю корректную позицию. Пересчёт при появлении ненулевой ширины.
  В новом экземпляре при переключении виджета или уходе со страницы — старт
  с начала, кроме уже существующего нативного смещения при гидратации.
- **Быстрые действия.** Переход к началу/концу, повторное нажатие, жест во время
  анимации или пересчёт при движении не создают новых карточек и не выходят за `0…S`.
- **Объём и направления.** Все карточки рендерятся, поскольку они нужны в
  готовом HTML. Размер набора задаёт запчасть, отдельного лимита не вводим.
  Первая версия рассчитана на текущие LTR-страницы Oysite; RTL-нормализация
  координат и вертикальная карусель не входят в объём.

### Ручная проверка

Автоматические unit-, компонентные и SSR-проверки не заменяют визуальную проверку.
Чек-лист ниже обязателен; инструменты разработчика допустимы для проверки границ,
но отдельный браузерный автотест не требуется.

- **Ширины контейнера.** Проверить 320, 375, 560, 768, 1024 и 1440 px, по 1 px
  ниже порогов и на самих порогах 584, 888 и 1192 px, а также один дробный размер.
  Узкие контейнеры открывать внутри широкого окна, а не только менять окно.
  В покое видны 1–4 целые карточки (или все, если их меньше), нет переноса
  и частично обрезанных карточек; промежутки соответствуют `--site-space-6`.
- **Короткие и длинные списки.** Проверить `N = 0/1/2/4/5` при `W = 1440px`
  и `K = 4`, список из 100 карточек, а также `N = 2` при `K = 1`. При `N = 1/2`
  карточки шириной `342px` стоят слева, остаток `1098/732px` остаётся справа;
  кнопок и счётчика нет. При `N = 4` окно заполнено без прокрутки. При `N = 5`
  после шага последняя карточка целиком доходит до правого края.
- **Шаги и границы.** Из начала пройти по одному нажатию до последней позиции
  и обратно. Проверить быстрые двойные нажатия, Home / End, недоступность кнопки
  на границе и то, что повторное нажатие не двигает ряд. После каждого шага
  видны только целые карточки, без частичной соседней.
- **Полоса и жесты.** На длинном списке убедиться, что горизонтальная полоса
  прокрутки визуально скрыта и не занимает высоту, но свайп, трекпад, колесо
  и нативные стрелки двигают ряд. После инерции или жеста позиция выравнивается
  по границе карточки; страница не прокручивается вбок. Проверить системную
  настройку «всегда показывать полосы прокрутки».
- **Resize и обновления.** Изменить ширину контейнера в начале, середине и конце,
  во время перехода, а также скрыть и снова показать контейнер. Затем уменьшить,
  дополнить и переставить список. Позиция сохраняет ожидаемый якорь,
  не выходит за границы, а панель управления появляется или скрывается.
- **Содержимое.** Проверить карточки с длинным непрерывным словом, высокой
  цитатой, изображением и без изображения. Текст не выходит за карточку,
  страница не получает горизонтального переполнения, разная высота не ломает ряд.
- **Клавиатура и фокус.** Пройти Tab и Shift+Tab, активировать кнопки Enter
  и Space, проверить стрелки, Home и End на области просмотра. Фокус не попадает
  в `inert`-карточки, остаётся на кнопке на границе, после перехода доступен
  в видимых карточках и покидает карусель обычным порядком.
- **Reduced motion, JS и гидратация.** При системном уменьшении движения переходы
  мгновенные, без промежуточной анимации; в обычном режиме позиция плавно
  доходит до цели. С отключённым JS проверить подсказку при переполнении,
  нативную прокрутку, фокус области просмотра и ссылки всех карточек.
  С JS убедиться, что ошибок и предупреждений гидратации нет.
- **Три поверхности.** Повторить основные проверки в публичной странице,
  живом редакторе и сохранённом предпросмотре. В админке выбрать карусель
  на вкладке «Виджет», сохранить и открыть `/admin/preview`; сравнить видимый
  диапазон, шаг и последнюю позицию. Переход обратно к сетке сохраняет настройки
  запчасти и общие отступы.
- **Устройства и доступность.** На реальном сенсорном устройстве, включая
  Safari/iOS, проверить медленный и резкий свайп, вертикальный скролл поверх
  секции, смену ориентации. На физическом трекпаде — горизонтальный жест
  и выравнивание. С экранным диктором (VoiceOver или NVDA) — доступное имя,
  недоступность кнопки на границе, одно объявление смены диапазона и отсутствие
  невидимых ссылок в обходе.

## 10. Критерии приёмки

Критерии проверяются вручную в браузере по чек-листу раздела 9 и дополняются
автоматическими unit-, компонентными и SSR-проверками. Допуск при визуальной
проверке границ — **1 CSS px** на дробные размеры и округление. Отдельные
браузерные автотесты для приёмки не требуются.

- При `N > 0` после остановки движения видны ровно `V = min(N, K)` **полностью**
  карточек с индексами `i…i + V − 1`. Соседняя карточка вне этого диапазона
  не видна; частичная видимость допустима только во время движения.
- **`0 < N < K`:** `i = S = 0`, левая грань первой карточки совпадает с левой
  гранью области просмотра, ширина каждой равна `C`. Справа остаётся
  `(K − N) × (C + G)`; это ожидаемое свободное место. Кнопок и счётчика нет.
- **`N ≥ K`:** в каждом окне видны ровно `K` целых карточек. Левая грань
  первой видимой карточки и правая грань последней совпадают с гранями области
  просмотра. При `i = S` последняя видимая карточка имеет индекс `N − 1`;
  её обрезка и пустой правый край недопустимы. При `N = K` контролов нет.
- Верхние координаты карточек совпадают, ширина каждой видимой карточки равна
  `C`, промежутки — `G`. Высоты карточек могут различаться. При `N = 0`
  карусель не отображается.
- Каждое обычное нажатие меняет `i` на `±1` с ограничением по границам;
  при `N ≤ K` панели управления нет. После изменения ширины или списка позиция
  сохраняет корректный якорь и удовлетворяет тем же условиям. Длинный текст
  не создаёт горизонтального переполнения страницы.
- Нативная полоса прокрутки визуально скрыта при переполнении; кнопки,
  клавиатура, свайп и трекпад работают. Без JS остаются доступны подсказка
  при переполнении, фокус области просмотра, нативная прокрутка и ссылки карточек.
- Пройдены автоматические unit-, компонентные и SSR/гидратационные проверки,
  а также ручной чек-лист: ширины, короткие и длинные списки, шаги, resize,
  клавиатура, сенсорное устройство, админка и экранный диктор. В консоли нет
  ошибок гидратации или дублирования ключей. Существующие виды остаются
  доступными, выбор по умолчанию не меняется.

## 11. План реализации по этапам

1. Утвердить спецификацию и политики ширины/фокуса.
2. Реализовать общий список, CSS-геометрию и нативную прокрутку, затем
   позиционирование, resize, клавиатуру и состояние кнопок. Добавить unit- и
   компонентные тесты.
3. Выделить переиспользуемые карточки, зарегистрировать два новых виджета,
   проверить данные, совместимость, отступы, SSR и гидратацию.
4. Выполнить ручную проверку по чек-листу: ширины, короткие и длинные списки,
   шаги, resize, свайпы, клавиатура, админка и устройства; устранить отклонения
   до выпуска.

### Компромиссы и решения на утверждение

1. **Автоматические пороги 584/888/1192px и стандартная ширина короткого списка.**
   Одна или две карточки в широком контейнере сохраняют ширину слота. Свободное
   место справа допустимо только для неполного ряда.
2. **Нативный свайп может пройти несколько карточек.** Строго один шаг
   относится к кнопкам и клавишам Left / Right. Нативное движение и высота по
   самой высокой карточке упрощают реализацию без собственного drag-движка и
   динамического изменения высоты.
3. **Полоса скрыта и до, и после гидратации.** Без JS доступность сохраняют
   подсказка, нативная прокрутка и ссылки. После гидратации дополнительные
   карточки доступны через кнопки и счётчик; вне окна применяется `inert`.

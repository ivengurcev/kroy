# Редактор страниц

**Статус:** редактор работает как SSR-приложение на Vyaz с клиентской гидратацией. API, авторизация и сохранение в БД пока не подключены.

## Файлы

| Файл | Ответственность |
|---|---|
| `editor/Editor.jsx` | Состояние страницы и операции над экземплярами |
| `editor/PartsPanel.jsx` | Выбор, добавление, удаление и перестановка запчастей |
| `editor/PartEditor.jsx` | Поля конкретного экземпляра |
| `editor/Field.jsx` | Выбор виджета по схеме |
| `editor/ListField.jsx` | Универсальный редактор массивов объектов |
| `editor/partModel.js` | Начальные значения и временные идентификаторы |
| `layout/Page.jsx` | Рендеринг списка запчастей |

`Field` и `ListField` работают по метаданным, а не по именам конкретных запчастей. Вложенные поля списка используют те же виджеты.

## Внутреннее состояние и документ страницы

Внутри React-редактора элемент имеет вид:

~~~js
{
    id: 'temporary-editor-id',
    part: '@kroy/contacts',
    props: { phone: '+7 999 123-45-67', socials: [] }
}
~~~

`id` нужен для стабильного React-ключа и операций над экземплярами (включая несколько одинаковых запчастей). Это **не часть контракта страницы**. В блоке «Данные страницы» он уже удаляется:

~~~js
const pageContent = content.map(({ part, props }) => ({ part, props }));
~~~

Данные для сохранения и публикации должны иметь только `{ part, props }`. После подключения API важно применять то же правило при отправке, а не сериализовать внутренний `content` напрямую.

## Работающие функции

- Добавление любой запчасти из сгенерированного реестра.
- Удаление, перестановка и независимое редактирование нескольких экземпляров одного типа.
- Начальные значения `props` по схеме.
- Поля ввода, текстовые области, числа, переключатели, выбор вариантов.
- `list`: добавление, удаление, перестановка элементов и изменение их вложенных полей.
- Живой React-предпросмотр и вывод публичного JSON страницы.

В прототипе `ListField` использует индексы как React-ключи элементов. Если появятся сложные компоненты с собственным состоянием, их ключи следует стабилизировать **в редакторе**, не загрязняя содержимое `props` служебными идентификаторами.

## Запуск

~~~bash
yarn install
yarn vyaz:build
yarn vyaz:serve
~~~

Открыть `http://localhost:3000/`. Команда `vyaz:build` сначала генерирует реестр и метаданные запчастей, затем собирает SSR- и клиентскую части через Vyaz.

## Реестр запчастей

`layout/Page.jsx` получает реестр компонентов извне. Редактор передаёт ему полный `dist/kroy/parts.mjs`; статический demo-сайт использует сокращённый `dist/kroy/site-parts.mjs`.

Работа ведётся маленькими проверяемыми задачами: обсуждение → поручение Codex → ручная проверка → следующая задача. Не следует реализовывать весь сборщик и публикацию одним изменением.

# Редактор и предпросмотр

Справочник текущего поведения административного интерфейса. Доступ защищён
Auth.js и серверной проверкой сайта; спорные права владельца описаны в
[requirements.md](requirements.md#сайты-и-доступ). Запуск development —
[infra/README.md](../infra/README.md).

## Маршруты и загрузка

`/admin` редактирует главную страницу через `GET /api/pages?path=/`;
`/admin/pages/:pageId` — выбранную через `GET /api/pages/:pageId`.
Старый суффикс `/edit` не является текущим маршрутом выбора страницы.
При открытии главной по UUID адрес приводится к `/admin`.

`/admin/pages` показывает дерево по сегментам URL; виртуальные группы для
отсутствующих родителей существуют только в UI. Ветки открыты по умолчанию,
строки и оформление используют общий `admin/ui/Tree.jsx`, как ListField.
Общий компонент отвечает за линии, зебру, иконки и расположение действий;
построение дерева страниц и редактирование списковых полей остаются отдельными.
Действующие перенаправления раскрываются отдельной кнопкой-счётчиком.
«Показать удалённые» включает удалённые записи и восстановление в том же дереве.
Каталог и материалы используют тот же Tree: разделы отображаются папками,
позиции и материалы — строками файлов. В каталоге открыта выбранная папка;
её содержимое загружается сервером с фильтрами и пагинацией по 50 позиций.
«Без раздела» остаётся отдельной папкой. В материалах разделы сворачиваются
независимо, а поиск, фильтр раздела/статуса и пагинация применяются к материалам.
Раздел без записей на текущей странице списка отличается от действительно пустого.
Действия создания, изменения и удаления остаются у соответствующих узлов.
Старый `/admin/pages/trash` открывает это же дерево с включённым переключателем.
Название страницы открывает редактор содержимого, иконка редактирования —
`/admin/pages/:pageId/settings`. Настройки заменяют рабочую область, используют
существующую форму, SEO, фиксированный `ActionFooter` и общий navigation guard.
`/admin/pages/new` использует эту же форму для создания, SEO доступно после создания.
Тип существующей страницы показан без возможности изменения, как и в прежнем API.

Административные разделы используют один постоянный лэйаут и навигацию Vyaz
через History API; Back/Forward обновляет текущий маршрут без пересоздания React
Root. Перед уходом с раздела при несохранённых изменениях показывается подтверждение.
При переключении между главным разделом настроек, оформлением, контактами и SEO компонент настроек не
пересоздаётся: черновики сохраняются. При переходах внутри этой группы, включая
Back/Forward, подтверждение не показывается. Кнопка сохранения и состояние нижней панели
относятся только к активному разделу; предупреждения об уходе и блокировка публикации
продолжают учитывать несохранённые изменения всех четырёх разделов.
В разделе `/admin/overview` выбирается шаблон сайта по умолчанию. Контакты,
включая email, редактируются в разделе «Контакты».
`/admin/preview` остаётся вне административного лэйаута.

Страница загружается клиентским эффектом при каждом изменении маршрута редактора,
до ответа показывается загрузка,
при ошибке — ошибка без подстановки demo-данных. Отдельный запрос
`/api/site/preview` получает тему, контакты, каталог и опубликованные отзывы.
Для материалов редактор дополнительно получает sample record/списки через
`admin/editor/materialPreview.mjs`; эти данные не сохраняются в content.

## Файлы и состояние

| Файл | Ответственность |
|---|---|
| `admin/editor/Editor.jsx` | Загрузка, сохранение, dirty state и операции над блоками |
| `admin/editor/EditorWorkspace.jsx` | Рабочая область и живой предпросмотр |
| `admin/editor/PartPicker.jsx`, `admin/editor/PartControls.jsx` | Выбор и управление блоками |
| `admin/editor/PartEditor.jsx` | Настройки данных и выбор/настройки виджета |
| `admin/editor/Field.jsx`, `admin/editor/ListField.jsx`, `admin/editor/ImageField.jsx` | Контролы по метаданным |
| `shared/partModel.js` (общая с API и CLI) | Начальные значения, временные id, смена view |
| `site/runtime/Page.jsx` | Общий вызов запчасти и рендер виджета |
| `admin/pages/PreviewPage.jsx` | Приватный предпросмотр сохранённого сайта |

Внутренний блок содержит временный id и публичные данные:

```js
{
    id: 'temporary-editor-id',
    part: '@kroy/services',
    props: { title: 'Услуги' },
    view: { name: '@kroy/services', props: {} }
}
```

При сохранении id удаляется, view сохраняется обязательно. Полный контракт и
правила совместимости — в [PARTS.md](PARTS.md). При загрузке view не подменяется;
страница без него требует миграции. Новый блок получает default widget из JSDoc.
Смена виджета сохраняет props запчасти и общие `spacingTop`/`spacingBottom`,
индивидуальные настройки нового виджета сбрасывает к defaults.

В редакторе блока используются общие Tabs: «Данные» с полями запчасти и «Виджет».
Если полей данных нет, остаётся только открытая вкладка «Виджет».
Её порядок: выбор совместимого виджета, «Размеры и отступы» (высота Hero,
если предусмотрена схемой, верхний и нижний отступы), непустые «Параметры виджета».
Поля обеих вкладок остаются смонтированными; переключение не меняет данные,
не сохраняет страницу и не сбрасывает локальный ввод. Другой блок открывает
собственный редактор с начальной вкладкой.

Есть добавление, удаление, перестановка блоков и независимые экземпляры одного
типа; поля простых типов, списков, изображений, выборок каталога и отзывов.
В административной шапке блока рядом с названием приглушённо показан его
технический идентификатор (`@kroy/...`). При открытии полей выполняется
плавная прокрутка к блоку с учётом закреплённой шапки; при prefers-reduced-motion
анимация отключена. Прокрутка не повторяется при вводе в полях.
`Field` работает по схеме, а не по имени запчасти. `ListField` показывает компактное
дерево: каждый элемент — строка, каждое поле схемы типа `list` — дочерний список.
Несколько дочерних списков одного объекта показываются отдельно, с собственным
добавлением. Ветки раскрываются кнопками; перемещение ограничено непосредственным
списком. Временные ключи и состояние раскрытия хранятся только в интерфейсе и
сохраняются при перестановке соседей. Служебные id в props не добавляются.

Тип `richtext` показывает общий Lexical-редактор материалов в широкой компоновке.
Сохранённое значение — Lexical JSON; исторические строки открываются как обычный
текст с сохранением абзацев и LF/CRLF. Само открытие не меняет данные страницы.
Для полей запчастей панель сокращённая: жирный/курсив/подчёркивание, два списка,
ссылка, горизонтальная линия (HR), Undo/Redo — без выбора типа абзаца.
Линия вставляется штатным HorizontalRulePlugin и сохраняется узлом Lexical
`horizontalrule`; изображение общего HR сайта она не использует.
В материалах используется полный
режим с кнопками «Абзац», H2 и H3. Списки обозначены SVG-иконками со строками
и маркерами/номерами. При вводе Composer не пересоздаётся; внешний сброс или другая
запись загружает новое значение и очищает историю. В модальном ListField richtext
меняет только локальный черновик; «Отмена» не меняет элемент, «Сохранить»
подтверждает его перед общим сохранением страницы. Публикация остаётся отдельной.

Название строки берётся из `itemSummary`, затем из `title`, `name` или подходящего
текстового поля; без текста — «Элемент №N». Строка сокращается многоточием,
не содержит изображений или форм. Допускается одно короткое дополнительное
значение, например цена; число дочерних элементов показано приглушённым счётчиком рядом с папкой.

Добавление и редактирование открывают общий Modal с локальным черновиком и
обычными Field, исключая поля `list`. Для соцсетей сохраняется специальный
`renderItem`; `createItem` задаёт начальные значения. «Сохранить» подтверждает
только объект в текущем черновике страницы. Отмена и Escape не меняют данные;
родитель сохраняет дочерние списки и их порядок. Удаление родителя с данными
в дочерних списках требует подтверждения удаления всех вложенных элементов.

Модальная форма вынесена порталом за пределы формы страницы, со своей
ValidatedForm. Дочерние элементы открываются из дерева, а не из родительского
редактора. Штатное кадрирование ImageField остаётся отдельным диалогом; его
Escape обрабатывается отдельно и не отменяет редактирование элемента.

## Сохранение, предпросмотр, публикация

В оформлении светлая и тёмная палитры остаются соседними колонками.
На узком экране название параметра располагается над парой значений,
светлое и тёмное значения остаются рядом. Горизонтальной прокрутки нет
ни в таблице, ни у страницы; поля HEX остаются доступны для редактирования.
Общий параметр «Геометрия → Толщина линии» (`--site-line-width`, 1px по умолчанию)
управляет всеми линиями публичного сайта: границами, разделителями, контурами
фокуса и контурными иконками. Он сохраняется в shared overrides и одинаков
для обеих палитр; производные толщины не редактируются отдельно.

Раздел `/admin/templates` управляет шаблонами. Редактор шаблона использует те же
контролы блоков, а «Содержимое страницы» показано как слот без собственных действий.
«Использовать шаблон» в редакторе страницы меняет окружающие блоки в живом просмотре.
Общие блоки можно редактировать по данным; виджеты, порядок и количество меняются
только в редакторе шаблона. Иконки объясняют область действия общих правок.

Глобальный футер находится внизу обоих редакторов, без структурных действий.
Его поля и общие свойства шаблона входят в один черновик вместе с документом.
«Отмена» сбрасывает черновик без записи. «Сохранить» отправляет изменённые части
через PUT документа. При конфликте версия не перезаписывается: можно перечитать
актуальный футер или шаблон, сохранив другие черновики. Название/путь страницы
меняются отдельно через PATCH. Сохранение не публикует сайт; черновики видны
только в живом редакторе. Подробности — [FOOTER.md](FOOTER.md) и [ROUTING.md](ROUTING.md).

В той же форме свойств страницы доступны вкладки «Основное», «SEO» и «Внешний вид»; у detail
шаблона SEO не редактируется, метаданные берутся из материала. Пустые SEO-поля
показывают значения сайта, но не копируют их в страницу. `/admin/seo` сохраняет
общие настройки отдельно от оформления и контактов. Изображения загружаются
общим `ImageField`, собственное изображение можно убрать для возврата к наследованию.
Правила и JSON-контракт — [SEO.md](SEO.md).

«Внешний вид» доступен после создания страницы, включая detail-шаблон.
Выбор темы и режима «Как на сайте» означает наследование, не копирование
глобальных настроек. Таблица токенов и выбор темы вынесены в общий
`AppearanceControls.jsx`, используемый также в оформлении сайта.
Поля показывают эффективные значения; изменение создаёт override, сброс
возвращает базу наследования, а не defaults глобальной темы.
Другая тема страницы использует свою цветовую базу, но наследует shared сайта.
Смена темы меняет только цвета: overrides палитр очищаются, типографика,
геометрия и отступы сохраняются и не зависят от выбора темы.
Изображение HR редактируется только на уровне сайта.
Appearance сохраняется вместе с другими свойствами через PATCH и участвует
в общем dirty state, отмене и navigation guard. Кнопка «Отмена» возвращает
сохранённые значения всех вкладок. Сохранение не публикует сайт.
Живой редактор сразу показывает изменения оформления из открытой формы;
отмена возвращает сохранённое оформление. Сохранение обновляет палитры редактора
из ответа PATCH, без перезагрузки. Живой редактор, сохранённый предпросмотр и
публичная сборка используют общий алгоритм разрешения оформления.
Выбор темы, шрифтов, единиц измерения и списки в основных/SEO-полях используют
общий SelectControl с клавиатурной навигацией. Режим темы на странице и сайте
использует общий ThemeModeControl; у страницы добавлен вариант «Как на сайте».

`/admin/preview?path=...` показывает сохранённые страницы и настройки из БД без
сборки, административной шапки и редакторских контролов. Есть плашка сохранённой
версии, адаптер внутренних URL и Back/Forward в пределах предпросмотра.
Отдельный предпросмотр сайта пока не поддерживает детальные шаблоны и показывает
для их адресов сообщение о недоступности. Sample опубликованного материала доступен
в живом редакторе самого шаблона; список материалов доступен и в сохранённом
предпросмотре. Это не просмотр старого опубликованного релиза и не история редакций.

Кнопка публикации использует приватный `POST /api/site/publish`, затем опрашивает
GET того же пути. Публикуется сохранённое состояние всего текущего сайта; при
несохранённых правках интерфейс запрещает публикацию с сообщением
«Сначала сохраните изменения» и не сохраняет форму автоматически. Повторный запуск активной
задачи сайта возвращает её статус; другая активная задача в этом процессе даёт
409. Межпроцессную блокировку и переключение Nginx выполняет общий CLI-процесс.
Подробности релизов и отката — в [infra/README.md](../infra/README.md).

## Действия, состояние форм и ошибки

`ActionFooter` закреплён внизу рабочей области, учитывает ширину бокового меню и
резервирует измеренную высоту в контенте. Кнопки с `disabled` или `aria-disabled`
не показываются. Если доступных действий нет, панель не рендерится, не резервирует
место и освобождает дополнительный отступ прокрутки. Экран передаёт в панель сами
элементы действий, а не компонент-обёртку, скрывающий доступность кнопок.
Кнопки и ограничения определяет экран; главная страница не получает действие
удаления. Списки показывают действия создания в своём контенте, без пустого футера.
На мобильных кнопки переносятся; изменение цвета панели использует короткий
переход с учётом `prefers-reduced-motion`.

Панель различает dirty state, сохранение, успех и ошибку текущего объекта.
Хедер содержит глобальные действия и отдельный статус публикации. После успешной
публикации мобильный интерфейс показывает номер релиза поверх содержимого, не меняя
высоту шапки; ошибки публикации также показываются поверх содержимого. После успешной
записи `apiRequest` уведомляет хедер повторно запросить `/api/site/publish`.
GET дополнительно возвращает `hasChanges` и идентификатор активного релиза;
источник актуальности — сравнение отпечатка БД с метаданными активного релиза,
а не событие браузера. Статус также обновляется при возвращении в окно и периодически.
Маршрут является ключом содержимого рабочей области, кроме общей группы оформления,
контактов и SEO, сохраняющей свои черновики; другие редакторы не переиспользуют
состояния и действия прежней формы.

`ValidatedForm` используется напрямую и через `AdminPanel as="form"` / `Card`.
Он проверяет ограничения полей до отправки, показывает сообщения рядом с полем,
задаёт `aria-invalid` / `aria-errormessage` и переводит фокус на первую ошибку.
Кнопка футера отправляет ту же форму через `form` или `requestSubmit`, поэтому
Enter проходит одинаковую проверку. Ошибки сбрасываются при исправлении поля.
Ответы API с ошибками валидации могут содержать
`{ error: 'Общее сообщение', fields: { slug: 'Такой адрес уже используется' } }`;
клиент передаёт `fields` форме через `formResponseError`, не выводя сырые исключения
сервера. Для ошибок изображений используется сообщение общего `ImageField`.

`useAutoSlug` использует существующую транслитерацию `slugifyPageTitle` и общую
проверку slug из `shared/materialFields.mjs`. В новом материале адрес следует за
названием до ручного ввода. Для существующих материалов генерация выключена.
Этот же хук формирует путь создаваемой страницы с префиксом `/`, сохраняя прежнее
поведение. У материала нет отдельной кнопки публикации: статус «Готов к публикации
сайта» сохраняет существующее значение `published`, а публичная версия меняется
только после публикации сайта. Обложка использует исходные пропорции ImageField.

Если запчасть сохранённого блока отсутствует в реестре, редактор сохраняет её
настройки в памяти и показывает заглушку, не прерывая загрузку страницы.
Такой блок можно переместить или удалить; редактирование его полей недоступно.
Для сохранения страницы неизвестный блок нужно удалить и при необходимости
добавить актуальную запчасть: API по-прежнему проверяет известные имена.

При отказе сохранения content API возвращает `details`: список `{ path, code, message }`.
Редактор показывает описание и путь поля, сохраняя несохранённые изменения.
В development обработчики API записывают метод, путь без query string, статус и
диагностику в stderr приложения (доступен через `bun run dev:logs`). Тела запросов,
cookies и заголовки авторизации не логируются.

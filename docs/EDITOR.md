# Редактор и предпросмотр

Справочник текущего поведения административного интерфейса. Доступ защищён
Auth.js и серверной проверкой сайта; спорные права владельца описаны в
[requirements.md](requirements.md#сайты-и-доступ). Запуск development —
[infra/README.md](../infra/README.md).

## Маршруты и загрузка

`/admin` редактирует главную страницу через `GET /api/pages?path=/`;
`/admin/pages/:pageId` — выбранную через `GET /api/pages/:pageId`.
Старый суффикс `/edit` не является текущим маршрутом выбора страницы.
При открытии главной по UUID адрес приводится к `/admin`.

Административные разделы используют один постоянный лэйаут и навигацию Vyaz
через History API; Back/Forward обновляет текущий маршрут без пересоздания React
Root. Перед уходом с раздела при несохранённых изменениях показывается подтверждение.
`/admin/preview` остаётся вне административного лэйаута.

Страница загружается клиентским эффектом при каждом изменении маршрута редактора,
до ответа показывается загрузка,
при ошибке — ошибка без подстановки demo-данных. Отдельный запрос
`/api/site/preview` получает тему, контакты, каталог и опубликованные отзывы.
Для материалов редактор дополнительно получает sample record/списки через
`admin/editor/materialPreview.mjs`; эти данные не сохраняются в content.

## Файлы и состояние

| Файл | Ответственность |
|---|---|
| `admin/editor/Editor.jsx` | Загрузка, сохранение, dirty state и операции над блоками |
| `admin/editor/EditorWorkspace.jsx` | Рабочая область и живой предпросмотр |
| `admin/editor/PartPicker.jsx`, `admin/editor/PartControls.jsx` | Выбор и управление блоками |
| `admin/editor/PartEditor.jsx` | Настройки данных и выбор/настройки виджета |
| `admin/editor/Field.jsx`, `admin/editor/ListField.jsx`, `admin/editor/ImageField.jsx` | Контролы по метаданным |
| `shared/partModel.js` (общая с API и CLI) | Начальные значения, временные id, смена view |
| `site/runtime/Page.jsx` | Общий вызов запчасти и рендер виджета |
| `admin/pages/PreviewPage.jsx` | Приватный предпросмотр сохранённого сайта |

Внутренний блок содержит временный id и публичные данные:

```js
{
    id: 'temporary-editor-id',
    part: '@kroy/services',
    props: { title: 'Услуги' },
    view: { name: '@kroy/services', props: {} }
}
```

При сохранении id удаляется, view сохраняется обязательно. Полный контракт и
правила совместимости — в [PARTS.md](PARTS.md). При загрузке view не подменяется;
страница без него требует миграции. Новый блок получает default widget из JSDoc.
Смена виджета сохраняет props запчасти, настройки нового виджета сбрасывает к defaults.

Есть добавление, удаление, перестановка блоков и независимые экземпляры одного
типа; поля простых типов, списков, изображений, выборок каталога и отзывов.
`Field` работает по схеме, а не по имени запчасти. `ListField` использует индексы
как React-ключи; служебные id не следует добавлять в сохраняемые props ради UI.

## Сохранение, предпросмотр, публикация

«Сохранить» отправляет `{ content }` через `PUT /api/pages/:pageId`.
Название/путь меняются отдельно через PATCH. Сохранение не публикует сайт;
несохранённые изменения видны в живом редакторе, но не в публичном релизе.

`/admin/preview?path=...` показывает сохранённые страницы и настройки из БД без
сборки, административной шапки и редакторских контролов. Есть плашка сохранённой
версии, адаптер внутренних URL и Back/Forward в пределах предпросмотра.
Отдельный предпросмотр сайта пока не поддерживает детальные шаблоны и показывает
для их адресов сообщение о недоступности. Sample опубликованного материала доступен
в живом редакторе самого шаблона; список материалов доступен и в сохранённом
предпросмотре. Это не просмотр старого опубликованного релиза и не история редакций.

Кнопка публикации использует приватный `POST /api/site/publish`, затем опрашивает
GET того же пути. Публикуется сохранённое состояние всего текущего сайта; при
несохранённых правках интерфейс запрещает публикацию с сообщением
«Сначала сохраните изменения» и не сохраняет форму автоматически. Повторный запуск активной
задачи сайта возвращает её статус; другая активная задача в этом процессе даёт
409. Межпроцессную блокировку и переключение Nginx выполняет общий CLI-процесс.
Подробности релизов и отката — в [infra/README.md](../infra/README.md).

## Действия, состояние форм и ошибки

`ActionFooter` закреплён внизу рабочей области, учитывает ширину бокового меню и
резервирует измеренную высоту в контенте. Кнопки с `disabled` или `aria-disabled`
не показываются. Если доступных действий нет, панель не рендерится, не резервирует
место и освобождает дополнительный отступ прокрутки. Экран передаёт в панель сами
элементы действий, а не компонент-обёртку, скрывающий доступность кнопок.
Кнопки и ограничения определяет экран; главная страница не получает действие
удаления. Списки показывают действия создания в своём контенте, без пустого футера.
На мобильных кнопки переносятся; изменение цвета панели использует короткий
переход с учётом `prefers-reduced-motion`.

Панель различает dirty state, сохранение, успех и ошибку текущего объекта.
Хедер содержит глобальные действия и отдельный статус публикации. После успешной
публикации мобильный интерфейс показывает номер релиза поверх содержимого, не меняя
высоту шапки; ошибки публикации также показываются поверх содержимого. После успешной
записи `apiRequest` уведомляет хедер повторно запросить `/api/site/publish`.
GET дополнительно возвращает `hasChanges` и идентификатор активного релиза;
источник актуальности — сравнение отпечатка БД с метаданными активного релиза,
а не событие браузера. Статус также обновляется при возвращении в окно и периодически.
Маршрут является ключом содержимого рабочей области: состояния и действия прежней
формы не переиспользуются новым редактором.

`ValidatedForm` используется напрямую и через `AdminPanel as="form"` / `Card`.
Он проверяет ограничения полей до отправки, показывает сообщения рядом с полем,
задаёт `aria-invalid` / `aria-errormessage` и переводит фокус на первую ошибку.
Кнопка футера отправляет ту же форму через `form` или `requestSubmit`, поэтому
Enter проходит одинаковую проверку. Ошибки сбрасываются при исправлении поля.
Ответы API с ошибками валидации могут содержать
`{ error: 'Общее сообщение', fields: { slug: 'Такой адрес уже используется' } }`;
клиент передаёт `fields` форме через `formResponseError`, не выводя сырые исключения
сервера. Для ошибок изображений используется сообщение общего `ImageField`.

`useAutoSlug` использует существующую транслитерацию `slugifyPageTitle` и общую
проверку slug из `shared/materialFields.mjs`. В новом материале адрес следует за
названием до ручного ввода. Для существующих материалов генерация выключена.
Этот же хук формирует путь создаваемой страницы с префиксом `/`, сохраняя прежнее
поведение. У материала нет отдельной кнопки публикации: статус «Готов к публикации
сайта» сохраняет существующее значение `published`, а публичная версия меняется
только после публикации сайта. Обложка использует исходные пропорции ImageField.

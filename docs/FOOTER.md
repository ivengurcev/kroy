# Обязательный футер сайта

`site/runtime/SiteFooter.jsx` — системный компонент, не запчасть/виджет.
`SiteApp` всегда выводит его ровно один раз после содержимого, включая страницы
материалов. Статический HTML, первый клиентский render, SPA и Back/Forward
используют один компонент. Ссылка **«Создано на Oysite» → https://oysite.ru/**
задана в коде без параметра отключения или изменения.

## Настройки и ссылки

`/admin/footer` использует обычные формы, ListField и сохранение текущего раздела.
Черновик сохраняется при переходах между оформлением, контактами, SEO и футером;
неопубликованные изменения учитывают все эти разделы.

`GET /api/site/settings` возвращает `footer`.
`PATCH /api/site/footer` полностью заменяет только `sites.footer_settings`:

```json
{
  "description": "Описание деятельности",
  "navigation": [{ "pageId": "aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa" }],
  "documents": {
    "privacyPageId": null,
    "offerPageId": null,
    "paymentPageId": null,
    "additional": [
      { "pageId": "bbbbbbbb-bbbb-bbbb-bbbb-bbbbbbbbbbbb" },
      { "label": "Внешний документ", "url": "https://example.org/document" }
    ]
  },
  "legal": { "name": "", "inn": "", "registrationNumber": "" }
}
```

Все поля необязательны. Максимумы: описание — 1000 символов, юридическое
наименование — 500, ИНН — 12, ОГРН/ОГРНИП — 15; каждый список — 50 элементов;
название внешнего документа — 200, URL — 2000. Неизвестные ключи и некорректные
типы отклоняются, включая любые попытки отключить футер/брендинг.
Внешние документы допускают HTTP(S) по общей безопасной проверке ссылок CTA;
относительные пути должны быть ссылками на страницы через UUID.
Абсолютные URL на любой домен текущего сайта также требуют выбора страницы
по UUID, чтобы не обходить проверку удалённых страниц и смену адресов.

При записи сервер под блокировкой сайта проверяет, что UUID принадлежат
действующим публичным страницам текущего сайта, не detail-шаблонам.
В публичных данных UUID разрешаются в текущие пути и названия. У стандартных
трёх документов подписи фиксированы по назначению, у остальных страниц —
актуальные названия. Удалённые, чужие и служебные страницы не выводятся.
Внутренние ссылки не подменяются строковыми URL.

Название берётся из `sites.name`; телефон, адрес и социальные сети — из
`contact_settings`. Общий email редактируется в `/admin/contacts`, там же хранится.
Нет независимых копий контактов. Старые контакты без email совместимы.
Социальные ссылки повторно проверяются перед публичным выводом.
Пустые группы и поля скрыты; документы и реквизиты не генерируются.

## Тема, сборка и публикация

`SiteRoot` использует выделенную оболочку `SiteTheme`, содержащую только
палитру и контекст разделителя. Платёжный `PaymentResult` остаётся в SiteRoot
в единственном экземпляре. Содержимое страницы и футер — соседние поддеревья:
страница получает собственную тему, футер — глобальную. Вложенных SiteRoot нет.
Живой редактор выводит футер один раз ниже блоков в глобальной теме.

Сборщик читает `footer_settings` в том же REPEATABLE READ снимке, что сайт
и страницы, и создаёт публичный `site-footer.mjs`. Он содержит разрешённые
ссылки, название, описание, реквизиты и год подготовки; административные
идентификаторы и сырые настройки не публикуются. SSR и гидратация импортируют
один снимок, API-запросов за настройками на статическом сайте нет.
Предпросмотр готовит ту же модель через `prepareSiteFooter`.

`footer_settings` входит в существующий SQL-fingerprint, контакты и страницы
уже учитывались. Сохранение не публикует сайт. Снимок футера находится в
HTML/JS релиза; обычный откат возвращает ранее опубликованный футер без
отката БД. XML sitemap и robots не меняются, HTML-карта сайта не создаётся.

## Ввод в эксплуатацию и проверка

Миграция: `db/migrations/202611260001_add_site_footer_settings.sql`.
Применить штатным `bun run db:migrate` в нужной среде до запуска новой версии API.
Существующие сайты получают `{}` и обязательный футер без ручного заполнения;
ранее опубликованные статические сайты нужно перепубликовать.

Автоматические проверки: схема, API и доменная изоляция, ссылки/контакты,
SSR/первая клиентская разметка, глобальная тема, навигация/Back/Forward,
черновики настроек и механизм публикации.
Вручную проверить сохранение/перезагрузку, опубликованный HTML всех типов страниц,
переходы и откат реального релиза, клавиатурную навигацию и ширины
320, 375, 768, 1024, 1440 px. Unit-тесты не заменяют визуальную проверку.

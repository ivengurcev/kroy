# Обязательный футер сайта

`@kroy/footer` — глобальная запчасть с одноимённым виджетом. `SiteApp` выводит её
через `Page` ровно один раз после всех блоков, включая страницы материалов и режим
без шаблона. Добавить второй футер в страницу или шаблон нельзя.
Ссылка **«Создано на Oysite» → https://oysite.ru** всегда выводится в нижней
части самого футера: справа от реквизитов на широких экранах, под ними на узких.
Текст, адрес и видимость не настраиваются. Для старых снимков без футера
сохраняется отдельный `OysiteBranding`; при наличии футера он не дублируется.

## Настройки и ссылки

Футер редактируется внизу страницы или шаблона стандартными контролами запчасти.
Отдельного экрана настроек нет. Правки настроек видны в живом просмотре и сохраняются
кнопкой основного редактора. Над контролом доступна подсказка о влиянии на весь сайт.
Правовые страницы сохраняются отдельно, из собственного диалога.

`GET /api/site/settings` возвращает `footer: { props, version }`.
`footerChanges: { props, expectedVersion }` в PUT страницы или шаблона полностью
заменяет `sites.footer_settings` в общей транзакции. Если версия устарела,
API возвращает `409 footer_conflict` и не применяет остальные правки. Формат `props`:

```json
{
  "description": "Описание деятельности",
  "navigation": [{ "pageId": "aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa" }],
  "documents": {
    "privacyPageId": null,
    "offerPageId": null,
    "paymentPageId": null,
    "additional": [
      { "pageId": "bbbbbbbb-bbbb-bbbb-bbbb-bbbbbbbbbbbb" },
      { "label": "Внешний документ", "url": "https://example.org/document" }
    ]
  },
  "legal": { "name": "", "inn": "", "registrationNumber": "" }
}
```

Все поля необязательны. Максимумы: описание — 1000 символов, юридическое
наименование — 500, ИНН — 12, ОГРН/ОГРНИП — 15; каждый список — 50 элементов;
название внешнего документа — 200, URL — 2000. Неизвестные ключи и некорректные
типы отклоняются, включая любые попытки отключить футер/брендинг.
Внешние документы допускают HTTP(S) по общей безопасной проверке ссылок CTA.
Внутренний документ создаётся как правовая страница сайта; добавлять его в
`footer_settings.documents` не требуется. Внешние ссылки на домены текущего сайта
не принимаются, чтобы не обходить проверку удалённых страниц и смену адресов.

При записи сервер под блокировкой сайта проверяет новые UUID навигации. Ранее
сохранённые ссылки на страницы в `documents` можно оставить без изменений или
удалить. Три прежних поля сохраняют свои подписи, дополнительные UUID используют
текущие названия страниц. Удалённые, чужие и служебные страницы не выводятся.

Название берётся из `sites.name`; телефон, адрес и социальные сети — из
`contact_settings`. Общий email редактируется в `/admin/contacts`, там же хранится.
Нет независимых копий контактов. Старые контакты без email совместимы.
Социальные ссылки повторно проверяются перед публичным выводом.
Пустые группы и поля скрыты; тексты документов и реквизиты не генерируются.

## Правовые страницы и переход со старых ссылок

«Правовые документы» в настройках футера показывает действующие страницы текущего
сайта с `is_legal_document = true`. «Добавить документ» и редактор строки открывают
общий диалог с названием, URL и полным Lexical-редактором. Успешное сохранение
сразу обновляет список и живой предпросмотр; черновики страницы, шаблона и
настроек футера остаются в основном редакторе. Удаление и восстановление находятся
в карте страниц.
Диалог редактирует текст первого `@kroy/document`; другие блоки документа и
страницы, их порядок, свойства и отображения сохраняются. Признак в этом диалоге
не переключается.

После миграции существующие строки `pages` и `footer_settings.documents` сохраняются
как есть. Прежние внутренние ссылки продолжают вести на те же доступные страницы,
внешние ссылки остаются редактируемыми. Чтобы перевести прежнюю обычную страницу
на автоматический список, откройте редактор страницы и включите чекбокс «Правовой
документ». Если `@kroy/document` ещё нет, редактор добавит пустой блок; существующий
текст автоматически не переносится и другие блоки не удаляются. Заполните блок
и сохраните страницу. UUID, URL, SEO и выбранный шаблон сохраняются; после
включения используется название страницы.
Ссылки на страницы других типов можно оставить прежними. Неподходящее
содержимое автоматически не заменяется. Если удалённый адрес переиспользован для
новой обычной страницы, старые ссылки на документ не переходят на неё.
Выключение признака убирает страницу из автоматического списка после сохранения,
но не удаляет её содержимое. Старые вручную сохранённые UUID-ссылки, если они
были, остаются отдельными прежними ссылками и при необходимости убираются вручную.

## Тема, сборка и публикация

`SiteRoot` использует выделенную оболочку `SiteTheme`, содержащую только
палитру и контекст разделителя. Платёжный `PaymentResult` остаётся в SiteRoot
в единственном экземпляре. Содержимое страницы и футер — соседние поддеревья:
страница получает собственную тему, футер — глобальную. Вложенных SiteRoot нет.
Оба живых редактора выводят футер один раз ниже блоков в глобальной теме.

Сборщик читает `footer_settings` в том же REPEATABLE READ снимке, что сайт
и страницы, и создаёт публичный `site-footer.mjs`. Он содержит разрешённые
ссылки, название, описание, реквизиты и год подготовки; административные
идентификаторы и сырые настройки не публикуются. SSR и гидратация импортируют
один снимок, API-запросов за настройками на статическом сайте нет.
Предпросмотр готовит ту же модель через `prepareSiteFooter`.

Автоматические ссылки берутся из действующих `standard`-страниц этого снимка:
подпись из `title`, URL из `path`. Если тот же адрес есть в прежних ссылках,
выводится одна автоматическая ссылка. `footer_settings` и полные записи страниц,
включая признак документа, входят в SQL-fingerprint. Сохранение не публикует сайт. Снимок футера находится в
HTML/JS релиза; обычный откат возвращает ранее опубликованный футер без
отката БД. XML sitemap и robots не меняются, HTML-карта сайта не создаётся.

## Ввод в эксплуатацию и проверка

Примените `db/migrations/202611270002_add_legal_documents.sql` штатной командой
`bun run db:migrate` до запуска новой версии API. Миграция добавляет признак
правовой страницы с начальным значением `false`; настройки футера и содержимое
страниц не меняются. Ранее опубликованные сайты используют старый релиз до
штатной перепубликации.

Автоматические проверки: схема, API и доменная изоляция, ссылки/контакты,
SSR/первая клиентская разметка, глобальная тема, навигация/Back/Forward,
черновики настроек и механизм публикации.
Вручную проверить сохранение/перезагрузку, опубликованный HTML всех типов страниц,
переходы и откат реального релиза, клавиатурную навигацию и ширины
320, 375, 768, 1024, 1440 px. Unit-тесты не заменяют визуальную проверку.

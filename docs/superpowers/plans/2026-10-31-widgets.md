# Widgets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add optional, contract-compatible display widgets over existing Kroy parts while preserving old `{ part, props }` pages and the current reviews slider.

**Architecture:** Parts and widgets declare the same opaque `@kroy-contract` string in JSDoc. `Page` keeps responsibility for resolving part data, then renders either the original part or the selected widget with separate `view.props`; editor and static builds consume generated full or used-only registries respectively.

**Tech Stack:** JavaScript, React 19, Yarn 4 PnP, esbuild, comment-parser, Vyaz, CSS Modules.

**Spec:** `docs/superpowers/specs/2026-10-31-widgets-design.md`

## Global Constraints

- Keep JavaScript; do not introduce TypeScript or new dependencies.
- Do not edit generated files under `dist/` manually.
- Do not change routing, the database schema, review APIs, publication, or deploy.
- Do not refactor unrelated parts or introduce dynamic imports.
- Persist only `{ part, props }` or `{ part, props, view: { name, props } }`; editor-only `id` never leaves state.
- Widget and part identifiers use `@kroy/` with kebab-case segments.
- Do not add tests or test infrastructure; project instructions reserve those for a separate request.
- Do not commit or push.

## Review Focus

- A legacy block without `view` must render and save byte-for-shape as `{ part, props }`, without an added empty field.
- A block with an unknown or contract-incompatible widget must be rejected by the page API and diagnosed by the site builder.
- Changing or removing a widget must never reset `part.props`, including manual review IDs and their order.
- Review selection (`mode`, `reviewIds`, `limit`) must run exactly once before either the slider or cards receive `reviews`.
- SSR and hydration must import the same used-widget registry and CSS Modules, including a site that uses no widgets.

- [ ] **Step 7: Inspect state boundaries**

# Основа платёжных интеграций

Принято уточнение пользователя: старый механизм ссылок оплаты удаляется полностью. Оформление оплаты, заказы, webhook, корзина и платёжный виджет не входят в задачу.

- [x] Миграции: site_payment_integrations с FK/UNIQUE и частичным UNIQUE(site_id) WHERE is_active; products.type NOT NULL DEFAULT service CHECK(service/goods); отдельное удаление старой колонки платёжной ссылки. Не применять к рабочей БД.
- [x] payments/providers.mjs: статический реестр только Prodamus, RUB, payformDomain (домен, допускается вставка HTTPS URL без пути); обязательная валидация, запрет неизвестных полей/провайдеров. sys не является настройкой сайта. В административный ответ поля настроек попадают только по явному allowlist.
- [x] db/sitePaymentIntegrations.mjs: чтение по site_id, сохранение без потери is_active, активация/деактивация в транзакции с блокировкой sites FOR UPDATE. Внутреннее хранилище общее для провайдеров, API допускает только реестр. Активация проверяет сохранённые настройки под блокировкой. Настройки других систем не удаляются.
- [x] api/sitePayments.mjs + server.mjs: приватные GET /site/payments, PATCH /site/payments/:provider (settings), PATCH /site/payments/:provider/activation (isActive boolean). Не передавать настройки в публичные источники сайта. Ошибки ввода400, внутренние500.
- [x] pages/SitePaymentsPage.jsx + components/admin/PaymentIntegrationEditor.jsx: существующие SiteSettingsLayout/Card/Button, простая схема полей, сохранение/активация/отключение, loading/saving/error, отображение активного провайдера. Не активировать несохранённые изменения.
- [x] Каталог: db/catalog.mjs, api/siteCatalog.mjs, CatalogEditor.jsx — service/goods, по умолчанию service. Удалить старый платёжный URL из нормализации/SQL/UI, кнопку покупки и её CSS из ProductCards.
- [x] Тесты реестра/API/хранилища/каталога/SSR форм. Для нескольких провайдеров — только тестовые данные хранилища, в реестре не добавлять фиктивные провайдеры. Отдельный PostgreSQL integration test с явным opt-in и проверкой изолированной БД: переключение и конкурентная активация/частичный индекс. Не запускать его без подготовленной тестовой БД.
- [x] Одна сборка редактора, существующие тесты основного проекта, поиск старых runtime ссылок, git diff --check и независимый обзор. Не запускать браузер/E2E, миграции, deploy, commit и push.

Выбор валидации: домен без протокола либо HTTPS URL с пустым путём/корневым слешем; без credentials, порта, query, fragment, localhost/IP. Не ограничивать недокументированным списком доменных зон. Настройки не сохраняются, если обязательный домен пуст/невалиден; активация дополнительно проверяет уже сохранённые значения атомарно.

Проверки: `yarn build` прошла; полный набор основного проекта — 40 файлов, 110 тестов: 104 успешно, 4 пропуска (включая новый PostgreSQL integration test без подготовленной изолированной БД), 2 прежние остановки на требованиях отдельных БД в auth.test.mjs и db/users.test.mjs. Профильные тесты реестра, API, хранилища, каталога и административных компонентов проходят. Независимый обзор существенных проблем не выявил. Runtime-обращений к старой платёжной ссылке не осталось; историческая SQL-миграция и старый dbmate schema snapshot сохраняются до применения миграций владельцем. Миграции/деплой/commit/push не выполнялись; браузер и настоящая конкурентная активация на PostgreSQL не запускались.

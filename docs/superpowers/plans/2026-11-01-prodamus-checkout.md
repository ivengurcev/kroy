# Оплата одной позиции через Prodamus

Основание: приложенное пользователем задание второго этапа; реализация разрешена, реальные платежи, deploy, commit/push запрещены.

Официальный протокол: https://help.prodamus.ru/payform/integracii/rest-api/instrukcii-dlya-samostoyatelnaya-integracii-servisov — POST form-urlencoded, do=link, sys, currency=rub, products[0][...], signature; строковые значения рекурсивно сортируются по ключам, JSON с escaped slash, HMAC-SHA256. Ответ — текстовая HTTPS ссылка, включая короткий адрес payform.ru.

- [x] Настройки: secretKey как password/server-only поле; приватный GET возвращает только признак сохранённого ключа. Пустое/отсутствующее значение при сохранении не стирает прежний ключ. JSONB upsert объединяет изменения под существующей блокировкой сайта. sys только PRODAMUS_SYS.
- [x] payments/prodamusDomain.mjs: только один корректный поддомен payform.ru для формы; платёжная ссылка только HTTPS на ту же форму или payform.ru. Без credentials/портов/протокольных обходов. Запросы запрещают redirects, имеют timeout; ошибка не возвращает данные запроса/ответа.
- [x] payments/prodamus.mjs: канонизация подписи, POST подписанного запроса, получение и проверка ссылки. payments/checkout.mjs: чтение актуального опубликованного товара текущего сайта и активной интеграции, проверка настройки/секрета/sys и цены, вызов конкретного провайдера. Без заказов, контактов покупателей и webhook.
- [x] db/catalog.mjs, db/sitePaymentIntegrations.mjs: узкие запросы товара и активной системы по site_id. Публичные GET /payments/status и POST /payments/start в server.mjs; начало принимает только productId, ошибки не раскрывают детали интеграции. Cache-Control:no-store.
- [x] ProductCards.jsx: проверка готовности оплаты после гидратации через API текущего домена, кнопка Купить только при готовности и положительной цене; loading/error, блокировка повторного запроса. Первоначально кнопка отсутствует и SSR совпадает с клиентом. Статическая сборка не читает и не экспортирует секреты; существующий Nginx проксирует /api с Host.
- [x] Тесты: подпись и точная форма запроса, SSRF/redirect/timeout/ошибки, цена и service/goods из БД, только productId, скрытые/чужие товары, отсутствие active/secret/sys, сохранение ключа без возврата в браузер, SSR кнопки и опубликованная сборка. Внешний API только моки.
- [x] Проверка: сборка редактора, существующие тесты, git diff --check и независимый обзор. Не запускать миграции, браузер/E2E, реальные платежи и deploy. Документировать условия реальной проверки.

Решения: доступность проверяется динамически, поэтому изменение ключа/активации/sys не требует публикации для проверки при открытии страницы. Для существующего опубликованного JS кнопку нужно получить следующей обычной публикацией обновлённого сайта. Нулевую/некорректную цену не отправлять в оплату. Валидация подписанной ссылки не допускает возврата signature браузеру.

Проверки: `yarn build` прошла; статическая сборка в тесте содержит каталог и same-origin checkout/status endpoints в app.js без секретов/SYS. После исправления найденного обзором случая encoded signature полный набор основного проекта — 44 файла, 130 тестов: 124 успешно, 4 integration-пропуска, 2 прежние остановки на требованиях изолированных БД (`auth.test.mjs`, `db/users.test.mjs`). Подпись проверена независимым HMAC-вектором, внешние API только замоканы. Новых миграций нет; пользовательский обновлённый db/schema.sql не изменялся агентом. Браузер, реальные платежи, deploy, commit/push не запускались.

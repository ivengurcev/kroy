# Запчасти данных и обязательные виджеты

Цель: запчасть синхронно готовит данные, виджет отображает их. Runtime старого формата не поддерживается. План и реализация запрошены пользователем в одном сообщении; дополнительных согласований не требуется.

Интерфейс запчасти: `prepare({ props, record, context, contacts, catalog, reviews }) -> data`. Виджет получает только `{ data, options, context }`. Настройки данных остаются в `part.props`, настройки отображения — в `view.props`.

- [x] Метаданные: `parsePartDoc.mjs` читает `defaultWidget`; `discoverParts.mjs` проверяет обязательный default, существование и точное совпадение контрактов. Регистрация через package.json исключает вспомогательные компоненты. Тесты с временными каталогами.
- [x] Данные и отображение: перенести JSX/CSS из каждой запчасти в виджет, функции подготовки хранить в `parts/*/prepare*.mjs`. Повторно использовать article-content/review-cards; слайдер — reviews-slider, общая форма — components/site. Фильтрация, подбор, нормализация исходных данных только в запчастях. Page вызывает prepare и рендерит выбранный виджет. Тесты чистых функций, SSR, payload гидратации и прежней разметки.
- [x] Редактор: partModel создаёт view по JSDoc, смена view сохраняет props и сбрасывает настройки виджета к defaults. Editor/PartEditor требуют view, загрузка не подменяет выбранный виджет. Тесты создания, смены и загрузки.
- [x] API и сборка: putPage требует view и совместимый контракт; generateSiteParts импортирует только используемые модули и отклоняет неполный формат. demo/page.json и seed используют обязательный view. Тесты API сохранения/загрузки и генерации.
- [x] Миграция: отдельный migratePageViews.mjs, dry-run по умолчанию, --apply явно. Вся таблица pages, включая корзину, одна транзакция и блокировка при записи; неизвестные части/виджеты останавливают операцию без потери данных. Сохранённые view и props остаются, недостающий view создаётся по метаданным. Повторный запуск ничего не меняет. Миграцию рабочей БД не запускать.
- [x] Проверка: все тесты основного проекта, одна yarn build, git diff --check через git-manager, независимое чтение изменений. Браузер и E2E не запускать. Не менять маршрутизацию, публикацию, SEO и оформление; не добавлять библиотеки, список статей, runtime fallback, коммиты и push.

Особые случаи: пустой список данных, черновики и удалённые записи; ручной порядок отзывов/товаров; props настроек не мутируют; несовместимый или отсутствующий view отклоняется; миграция сохраняет порядок, корзину и уже выбранные виджеты.

Проверка: `yarn build` прошла; полный прогон 30 тестовых файлов основного проекта — 70 успешно, 3 пропуска по integration flags, 2 остановки на требованиях отдельных БД (`auth.test.mjs`, `db/users.test.mjs`). Независимый обзор существенных проблем не выявил. Проверены серверная и клиентская сборки виджетов, совпадение начальной разметки после сериализации payload и CSS Modules; настоящий hydrateRoot и взаимодействия в браузере не запускались по правилам проекта. Миграция проверена на подставном DB-клиенте и к рабочей БД не обращалась.

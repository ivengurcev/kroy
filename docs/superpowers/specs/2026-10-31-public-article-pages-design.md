# Публичные страницы статей: дизайн

## Цель

Добавить в статическую сборку Kroy список опубликованных статей по `/articles` и отдельные страницы `/articles/:slug`. Новые или изменённые статьи появляются на публичном сайте только после следующей ручной публикации сайта.

## Текущая архитектура и подход

`scripts/buildSite.mjs` читает данные сайта, генерирует общие модули в `dist/kroy`, запускает SSR для набора статических URL, затем собирает клиентскую гидратацию. `scripts/renderSite.jsx` и `scripts/hydrateSite.jsx` импортируют один и тот же реестр страниц и данные сайта. `SiteApp` уже поддерживает client-side переходы по известным страницам внутри общей темы.

Рассмотрены два подхода:

1. Расширить `SiteApp` отдельными данными статей и рендерить два вида article routes внутри существующих `SiteRoot` и маршрутизатора. Сборщик добавляет нужные URL в обычный SSR список, а SSR и клиент импортируют один generated-модуль опубликованных статей. Это выбранный подход: он использует текущие точки SSR/гидратации и не дублирует маршрутизацию.
2. Создать отдельные entry points и маршрутизатор статей. Это дублировало бы текущие механизмы, поэтому не подходит заданным ограничениям.

## Требования и решения

- В рамках одной `REPEATABLE READ` транзакции сборки выбирать статьи только текущего сайта со статусом `published`, сортируя по `published_at DESC`.
- Генерировать `/articles` всегда, включая пустой список, и по одной странице для каждой опубликованной статьи.
- Публичный generated-модуль содержит только опубликованные статьи и поля, нужные для списка/полной страницы; черновики не попадают в HTML или app.js.
- Страница списка показывает обложку при наличии, заголовок, краткое описание и дату; вся карточка ведёт на slug URL. Полная страница показывает заголовок, дату, обложку и содержимое.
- Read-only React renderer обрабатывает paragraph, h2/h3, bold, italic, underline, bullet/numbered lists и links. React экранирует текст. URL разрешает HTTP(S), `mailto:`, `tel:` и внутренние относительные адреса; опасные схемы не превращаются в ссылки.
- Формат отображаемой даты — русская локаль, дата без времени в UTC, чтобы SSR и гидратация давали одинаковую разметку.
- Конфликтовать не должны `/articles` и каждый `/articles/:slug` с активными страницами, исходными/целевыми URL редиректов и удалёнными страницами. Ошибка сборки указывает конфликтующий путь.
- Обложки копируются из существующего media storage в `assets/articles/`; данные ссылаются на release asset URL.
- Редактирование статей, API, база данных, публикация и deploy не меняются.

## Не входит

Публичная админка/редактор, новые API, изменение схемы БД, отдельная маршрутизация, SEO-настройки, видео, Telegram и кросспостинг.

## Проверка

Проверить пустой сайт и сайт с опубликованными статьями вместе с черновиками; убедиться, что черновики отсутствуют в сгенерированных HTML и app.js. Проверить прямые статические URL списка и статьи, одинаковое разрешение данных в SSR и гидратации, безопасный вывод поддерживаемых Lexical узлов/ссылок и копирование/загрузку обложек. Публикацию или deploy не запускать.

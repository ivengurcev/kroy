# Метаданные запчастей — дизайн

## Цель

Добавить к каждой запчасти отображаемое название и категорию, не меняя её
технический идентификатор или формат данных страницы.

## Источник метаданных

Полный JSDoc-блок непосредственно перед `export default` поддерживает:

```js
/**
 * @kroy-title Первый экран
 * @kroy-category Основное
 * @param {string} props.title - Заголовок
 */
```

`@param` и `@kroy` остаются источником схемы редактируемых полей. `parsePartDoc()`
возвращает один объект `{ title, category, fields }`, а `discoverParts` записывает
в `parts.json` эти три значения для каждого идентификатора.

## Совместимость

Если новая аннотация отсутствует, генератор выводит название из последнего
сегмента `@kroy/*` и назначает категорию `Другое`. Идентификаторы `@kroy/*`,
импорты компонентов и сохранённый объект `{ part, props }` не меняются.

## Интерфейс

`PartPicker` ищет одновременно по ID, названию и категории, отображает
результаты сгруппированными по категории и сохраняет существующий выбор
технического идентификатора. `EditorWorkspace` и `PartEditor` показывают
название из метаданных с тем же fallback.

## Границы

- Нет реестра категорий, зависимостей или дублирования полей в `package.json`.
- Обновляются Hero, Services и одна простая запчасть как примеры аннотаций.
- Формат JSDoc описывается рядом с существующей документацией разработки.

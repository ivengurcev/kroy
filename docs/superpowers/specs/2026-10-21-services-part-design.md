# Запчасть Services

## Цель

Добавить универсальную запчасть `@kroy/services` с категориями и вложенными
услугами. Данные редактируются существующими `Field` и компактным `ListField`,
а публичный компонент использует токены `SiteTheme` и нативные раскрывающиеся
секции.

## Метаданные JSDoc

`scripts/parsePartDoc.mjs` продолжает строить существующую схему
`{ type: 'list', fields }`, но `parseType` рекурсивно разбирает массивы
объектов внутри массивов объектов.

Поля объекта разделяются только по запятым верхнего уровня. Разделяющее имя и
тип двоеточие также ищется на верхнем уровне с учётом глубины `{}`, `[]` и
`()`. Это сохраняет прежние примитивы, select-типы и плоские списки и позволяет
разобрать тип вида:

```text
{title: string, items: {name: string, price: string, note: string}[]}[]
```

Существующий `findField` проходит по `fields` на любой глубине, поэтому
настройки `@kroy categories.items.name ...` применяются без нового формата
метаданных.

## Стабильная идентичность ListField

Каждый экземпляр `ListField` хранит рядом с массивом данных параллельный массив
UI-ключей. `useId()` используется только как префикс экземпляра, а каждый ключ
получает последовательный номер локального счётчика.

UI-ключи не записываются в `props`. Обычное изменение полей не создаёт новый
ключ. При добавлении, удалении и перестановке массив ключей синхронно меняется
до передачи нового массива данных через `onChange`.

Раскрытый элемент и открытое меню определяются по UI-ключу. Поэтому после
перестановки элемент сохраняет раскрытие, а вложенный `ListField` перемещается
вместе со своим React-поддеревом и локальным состоянием.

## Внешнее обновление списка

`ListField` запоминает последний массив, переданный через собственный
`onChange`. Если следующее значение совпадает с ним по ссылке, обновление
считается подтверждением собственной операции и существующие ключи
сохраняются.

Если `value` заменён другим массивом, который текущий `ListField` не передавал,
обновление считается внешним. Для всего массива создаются новые UI-ключи,
раскрытие и меню сбрасываются. Это не позволяет состоянию перейти к элементам
другой запчасти или другой версии данных.

## Компонент Services

Создаются:

```text
parts/services/
  package.json
  Services.jsx
  services.module.css
```

Публичные props:

- `title` — заголовок секции;
- `eyebrow` — необязательная надпись;
- `categories` — категории с `title` и списком `items`;
- каждый элемент `items` содержит `name`, строковый `price` и необязательный
  `note`.

Полный JSDoc-блок непосредственно перед `export default` описывает структуру и
подписи вложенных полей. Компонент не содержит предметных названий, цен или
начальных данных.

## Раскрытие категорий

Категория рендерится отдельным компонентом на основе `details`/`summary`. Его
локальное состояние `isOpen` первоначально равно `true` и синхронизируется с
нативным событием `toggle`. Пользователь может независимо закрыть или открыть
любые категории; последующий React-рендер не возвращает закрытую категорию в
начальное состояние.

Это оставляет услуги видимыми в `inert`-предпросмотре редактора без сложного
контроллера аккордеона.

## Визуальная композиция

Корневая обёртка запчасти объявляет CSS container. На широком контейнере
заголовок находится слева, а вертикальный список категорий — справа. Категории
разделяются тонкими линиями; карточки, тени и яркие рамки отсутствуют.

В раскрытой категории название услуги располагается слева, цена справа, а
примечание — под названием. На узком контейнере заголовок располагается над
списком, а строки услуг переходят в одноколоночную компоновку.

Цвета, шрифты, контейнер, базовые интервалы и отступы берутся из
`SiteTheme.module.css`. Специфичная геометрия остаётся локальной в CSS Module.

## Границы

Не изменяются Hero, `parts/section/Main.jsx`, API, PostgreSQL, Vyaz, публикация
и дизайн-токены. Новые зависимости, отдельный редактор услуг и служебные ID в
сохраняемых данных не добавляются.

## Проверка

Выполняются только:

1. `git diff --check`;
2. `yarn vyaz:build`.

Пользователь вручную проверяет создание и раскрытие категории, вложенное
добавление услуги, изменение цены, перестановку элементов и сохранение
правильного состояния вложенных редакторов.

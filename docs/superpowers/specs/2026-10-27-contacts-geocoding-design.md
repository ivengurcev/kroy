# Поиск координат для контактов

## Цель

Добавить в inline-редактор `@kroy/contacts` поиск координат по адресу через Geoapify, не раскрывая ключ в браузере и не меняя формат данных страницы.

## Подход

Серверный `POST /api/geocode` защищён существующим `private: true`. Он принимает только адрес, ограничивает его длину, вызывает `https://api.geoapify.com/v1/geocode/search` с `text`, `limit=5`, `lang=ru`, `format=json` и ключом из `GEOAPIFY_API_KEY`. Ответ ограничивается отображаемым адресом, широтой, долготой и данными атрибуции; ключ, полный ответ провайдера и адреса не логируются.

В редакторе `PartEditor` передаётся технический идентификатор запчасти. Только для `@kroy/contacts` после поля `address` отображается локальный `ContactsAddressSearch`. Поиск запускается кнопкой, показывает состояние запроса, до пяти вариантов, отсутствие результата и ошибку. Выбор вызывает существующий `onPropChange` отдельно для `latitude` и `longitude`; адрес остаётся неизменным, ручное редактирование координат сохраняется.

## Ошибки и атрибуция

Пустой или чрезмерно длинный адрес получает `400`. Отсутствие `GEOAPIFY_API_KEY` даёт понятный `503`; ошибки Geoapify преобразуются в нейтральный `502`. Под результатами отображается атрибуция, возвращённая Geoapify для источника данных, с исходной ссылкой. Она не сохраняется в странице.

## Ограничения

- Не использовать Nominatim и не добавлять зависимости.
- Не менять публичную Leaflet/OSM-карту, JSDoc-поля, формат `{ part, props }`, тему и публикацию.
- Добавить `GEOAPIFY_API_KEY=` только в `.env.example`; фактический ключ остаётся в `.env`.
- Проверка: `git diff --check` и один `yarn vyaz:build`; браузерные тесты не запускаются.

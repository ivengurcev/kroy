# Toast публикации и тема статического сайта — дизайн

## Цель

Сделать ход и результат публикации заметными, но временными, а опубликованный
сайт — визуально идентичным сохранённым настройкам оформления и preview.

## Toast

`AdminHeader` показывает единственный fixed toast по центру внизу viewport.

- Пока задача имеет статус `building` или `publishing`, toast остаётся видимым.
- После `success` или `error` toast автоматически скрывается через пять секунд.
- Таймер создаётся только для терминального состояния, очищается при размонтировании,
  начале новой публикации и смене результата.
- Само серверное состояние задачи не удаляется: скрывается только его UI-сообщение.

## Снимок темы для статического сайта

`site:build` читает `theme_id`, `theme_mode` и `theme_overrides` в той же
read-only транзакции, что и страницы. Он рассчитывает обе палитры функцией
`getThemeTokens()` и создаёт в `dist/kroy` небольшой модуль со снимком:

```js
export const theme = { mode, light, dark };
```

И `renderSite.jsx`, и `hydrateSite.jsx` импортируют этот модуль и передают его
в один общий путь `SiteApp` → `SiteRoot`. Так серверная разметка и первая
клиентская отрисовка используют одинаковую светлую палитру.

Для режимов `light` и `dark` выбирается соответствующая палитра. Для `system`
`SiteRoot` после гидратации подписывается на `prefers-color-scheme` и меняет
палитру при изменении системного режима. Initial SSR/client state остаётся
светлым, поэтому React не получает mismatch. Preview передаёт тот же объект
темы и использует этот общий механизм, без собственной реализации `matchMedia`.

## Изоляция токенов

Публичный `SiteRoot` применяет только ключи `--site-*` к публичному поддереву.
`AdminTheme.module.css` не импортируется в статические entry points и остаётся
источником токенов только для административных компонентов. Плашка preview
может использовать admin-тему в приватной странице, но она не входит в
собираемый публичный сайт.

## Границы

- Не меняются модель тем, `getThemeTokens()`, публикация релизов, Nginx и API.
- Не добавляются зависимости и новая система тем.
- Не меняется структура хранимых настроек.

## Проверка

- Успех и ошибка публикации исчезают через пять секунд; прогресс остаётся до
  завершения; новая публикация не наследует старый таймер.
- `light`, `dark` и `system` в статическом сайте используют сохранённые
  переопределения; system реагирует на смену системной схемы.
- Первый HTML и первая клиентская отрисовка имеют одинаковые inline `--site-*`
  значения, а админские `--color-*` не присутствуют в публичном bundle.

# Интеграция нового интерфейса редактора

## Цель

Заменить старую разметку редактора новой административной оболочкой из
`editor/layout-preview/`, сохранив существующую загрузку, редактирование и
сохранение страниц. После интеграции в проекте остаётся один редактор на
маршрутах `/admin` и `/admin/pages/:pageId/edit`.

## Границы ответственности

`Editor.jsx` остаётся владельцем состояния и операций:

- загруженная страница (`id`, `title`, `path`, `content`);
- статус загрузки и сохранения, а также наличие несохранённых изменений;
- выбранная запчасть;
- добавление, удаление и перемещение запчастей;
- изменение свойств и сохранение страницы.

`AdminShell` и вложенные компоненты получают данные и обработчики через props.
Они не выполняют запросы к API и не создают собственную модель страницы.

Существующие `Page`, `PartEditor`, `Field`, `ListField`, `partModel`, реестр
`parts` и JSDoc-метаданные остаются источниками рендеринга и редактирования.

## Состояние и загрузка

После успешного GET `Editor.jsx` сохраняет идентификатор, название, путь и
содержимое страницы. Элементы `content` получают временные `id` через
`createPart()` как сейчас. Первым выбранным элементом становится первая
запчасть страницы; для пустой страницы выбор равен `null`. После загрузки
`isDirty` равен `false`, поэтому страница отображается как сохранённая.

Загрузка и ошибка отображаются внутри новой оболочки. Демонстрационные данные
и fallback-содержимое не используются.

Сохраняемый документ по-прежнему формируется как массив `{ part, props }` без
внутренних `id`.

## Выбор и операции с запчастями

Предпросмотр отображает настоящие компоненты в порядке `content`. Каждый
компонент получает внешний технический контейнер, отвечающий только за выбор и
рамку; внутренняя разметка и стили запчасти не изменяются.

Клик по контейнеру выбирает запчасть. Клик по ссылке внутри предпросмотра также
выбирает блок, но отменяет переход. Выбранный `id` не меняется при обновлении
props и перемещении.

После добавления выбирается созданная запчасть. После удаления выбирается
элемент, занявший тот же индекс, либо предыдущий элемент, если удалён последний.
Для пустой страницы выбор сбрасывается.

В инспекторе размещаются:

- выбор доступной запчасти и кнопка добавления;
- удаление выбранной запчасти;
- перемещение выбранной запчасти вверх и вниз;
- `PartEditor` для свойств выбранной запчасти.

Если запчасть не выбрана, инспектор показывает понятное пустое состояние и
оставляет доступным добавление.

## Компоненты интерфейса

- `AdminShell` — раскладка, состояния загрузки и общая композиция.
- `AdminHeader` — логотип, ссылка на карту страниц, название и путь страницы;
  нереализованные действия остаются отключёнными.
- `EditorToolbar` — режим редактора, реальный статус сохранения и кнопка,
  вызывающая `savePage`; история остаётся отключённой.
- `EditorWorkspace` — настоящий предпросмотр и инспектор.
- `BlockInspector` — операции над выбранной запчастью и существующий
  `PartEditor`.
- `EditorFooter` — пока только статический выбор устройства без изменения
  ширины предпросмотра.

Переиспользуемые визуальные компоненты (`Button`, `Tabs`, `Card`,
`StatusIndicator`, `SegmentedControl`) остаются презентационными.

## Состояние и статусы сохранения

Статус запроса и наличие локальных изменений учитываются отдельно:

- после загрузки: `isDirty = false` — «Сохранено»;
- после изменения: `isDirty = true` — «Есть несохранённые изменения»;
- во время запроса: `saveStatus = saving` — «Сохранение…», кнопка
  заблокирована;
- после успешного сохранения актуальной версии: `isDirty = false` —
  «Сохранено»;
- после ошибки: `saveStatus = error` — «Не удалось сохранить», локальные
  изменения остаются.

Любое изменение содержимого устанавливает `isDirty = true`, переводит
`saveStatus` в `idle` (если запрос сейчас не выполняется) и увеличивает номер
локальной ревизии. До успешной загрузки и при отсутствии изменений кнопка
сохранения недоступна.

При начале сохранения фиксируются снимок `pageContent` и номер текущей ревизии.
Успешный ответ сбрасывает `isDirty` только в том случае, если номер локальной
ревизии не изменился за время запроса. Если пользователь изменил страницу во
время сохранения, завершившийся запрос подтверждает только отправленный снимок:
после ответа интерфейс снова показывает «Есть несохранённые изменения», а
кнопка сохранения становится доступной для новой версии. Ошибка запроса никогда
не сбрасывает `isDirty`.

## Стили

Новая оболочка использует существующие CSS Custom Properties и CSS Modules.
Старый `editor/editor.css` больше не подключается редактором.

`Field`, `ListField` и `PartEditor` получают модульные стили, чтобы поля не
зависели от старых глобальных классов. Большой модуль оболочки разделяется
только там, где стили принадлежат самостоятельному компоненту; декоративные
заглушки удаляются вместе с неиспользуемыми правилами.

Стили публичных компонентов не изменяются. Техническая рамка выделения не
должна задавать стили их потомкам.

## Маршруты

`/admin` и `/admin/pages/:pageId/edit` продолжают вести на `Editor.jsx`.
Временный маршрут `/admin/layout-preview` удаляется. Маршруты списка страниц и
корзины не изменяются.

## Обработка ошибок

Сохраняется существующее поведение API: ошибка загрузки заменяет рабочую
область сообщением, ошибка сохранения не удаляет локальные изменения.
Неизвестная запчасть продолжает обрабатываться существующим `Page`.

## Проверка

Техническая проверка ограничена командами:

1. `git diff --check`;
2. `yarn vyaz:build`.

Пользователь вручную проверяет загрузку, выбор, поля, списки, добавление,
удаление, перемещение, сохранение и адаптивность в браузере.

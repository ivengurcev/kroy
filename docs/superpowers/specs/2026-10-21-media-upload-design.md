# Загрузка и хранение изображений

## Архитектура

Изображения хранятся неизменяемыми файлами в `data/media/<site-id>/`, а
PostgreSQL хранит метаданные и принадлежность сайту. UUID и расширение по
сигнатуре формируют серверный путь; исходное имя не используется.

`POST /api/media` разбирает один multipart-файл, ограничивает его размер 10 МБ,
проверяет сигнатуру JPEG/PNG/WebP, определяет сайт по `Host`, записывает новый
файл и строку `media` в рамках согласованной операции. При ошибке транзакция
откатывается, а уже записанный файл удаляется.

`GET /api/media/:id` одним JOIN проверяет домен и принадлежность, читает только
валидный путь из хранилища и возвращает неизменяемый ответ с долгим кешем.

`ImageField` загружает файл через относительный `/api/media`, сохраняет прежнее
значение при ошибке и вызывает `onChange(url)` только после успеха. `Field`
выбирает его для `schema.type === 'image'`; рекурсия `ListField` не меняется.

## Границы

Нет удаления, оптимизации, медиабиблиотеки, новых зависимостей или изменений
публикации. API изменения данных остаётся локальным и не считается безопасным
для публичного доступа без будущей авторизации.

## Проверка

Только `git diff --check` и `yarn vyaz:build`; сценарии загрузки проверяются
вручную.

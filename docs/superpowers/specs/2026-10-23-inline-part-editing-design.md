# Inline-редактирование запчастей

## Цель

Убрать постоянный инспектор свойств и редактировать одну выбранную запчасть
непосредственно на её месте в структуре страницы. Существующая модель данных,
формы полей, операции над запчастями и сохранение страницы остаются без
изменений.

## Владение состоянием

`Editor.jsx` продолжает владеть содержимым страницы, выбранной запчастью,
признаком несохранённых изменений и сохранением. Его `updateProp` остаётся
единственным способом изменения свойства запчасти.

`EditorWorkspace` хранит локальный `editingPartId`. Это состояние определяет
только способ отображения запчасти и не входит в сохраняемый документ.
Одновременно редактируется не более одной запчасти:

- нажатие «Редактировать» устанавливает ID выбранной запчасти;
- открытие другой запчасти заменяет текущий `editingPartId`;
- «Закрыть» сбрасывает `editingPartId`;
- удаление редактируемой запчасти сначала закрывает форму;
- перемещение и изменение свойств не меняют ID и не закрывают форму.

При открытии формы запчасть также передаётся в существующий
`onSelectPart`, поэтому текущее выделение и поведение выбора сохраняются.

## Обычное отображение запчасти

Неактивная запчасть отображается существующим способом через `SiteRoot` и
`Page`. Публичное содержимое остаётся внутри `inert`-обёртки с отключёнными
pointer events, поэтому ссылки, кнопки и поля публичной запчасти не выполняют
действий в редакторе.

Существующий `PartControls` остаётся вне `inert`. В него добавляется
подписанная кнопка «Редактировать» рядом с перемещением и удалением. Кнопка
получает существующую SVG-иконку `edit`, нативное доступное название и
останавливает всплытие так же, как остальные административные действия.

Точки добавления между запчастями, поповер выбора, перемещение вверх/вниз и
удаление сохраняют текущие обработчики и доступность.

## Inline-форма

Если `item.id === editingPartId`, вместо публичного `Page` внутри технического
контейнера запчасти отображается административная inline-форма. Она содержит:

- название/идентификатор запчасти;
- кнопку «Закрыть»;
- существующий `PartEditor`;
- существующие поля из `metadata[item.part].fields`.

`PartEditor` получает актуальные `item.props`. Его `onPropChange` напрямую
вызывает существующий `onPropChange(item.id, name, value)`. Промежуточный
черновик, отдельное сохранение формы и новая система полей не создаются.
Изменения немедленно обновляют состояние страницы и отмечают её изменённой;
кнопка сохранения страницы остаётся единственным серверным сохранением.

`Field`, `ListField`, `ImageField`, вложенные списки и JSDoc-метаданные не
изменяются. Благодаря стабильному внутреннему ID запчасти несколько экземпляров
одного типа продолжают иметь независимые свойства.

Inline-форма находится вне `SiteRoot`, чтобы административные поля не
наследовали публичную тему. Внешняя область формы занимает место исходной
запчасти в потоке, визуально выделяется границей и фоном административной темы.
Внутреннее содержимое ограничивается удобной максимальной шириной и
центрируется на широком экране. На узком экране оно занимает всю доступную
ширину; поля и кнопки получают `min-width: 0` и не создают горизонтальную
прокрутку.

## Рабочая область

`EditorWorkspace` становится одноколоночным. Постоянный `BlockInspector`
больше не рендерится. Сам файл инспектора можно оставить без изменений: его
удаление не требуется для результата и было бы сопутствующим рефакторингом.

Основная ширина отдаётся странице. Существующие контейнеры запчастей,
выделение, панель управления и точки вставки сохраняются. Inline-форма не
позиционируется поверх соседних элементов и увеличивает высоту страницы в
обычном потоке.

## Footer и прокрутка

`EditorFooter` переносится из отдельной нижней строки `AdminShell` внутрь
прокручиваемого `main`, сразу после `EditorWorkspace`. Корневая Grid-оболочка
редактора использует две строки:

```css
grid-template-rows: auto minmax(0, 1fr);
```

Шапка остаётся на месте, а `main` продолжает владеть прокруткой. Footer
располагается после фактического содержимого страницы и прокручивается вместе
с ним, а не закрепляется у нижней границы окна.

## Изменяемые области

Минимальный набор файлов:

- `components/admin/AdminShell.jsx` и его CSS Module;
- `editor/EditorWorkspace.jsx` и его CSS Module;
- `editor/PartControls.jsx` и его CSS Module;
- `editor/EditorFooter.module.css`.

Если для inline-формы достаточно правил в `EditorWorkspace.module.css`, новый
компонент или отдельный CSS Module не создаётся. `Editor.jsx`, `PartEditor`,
`Field`, `ListField` и `BlockInspector` изменяются только если реализация
обнаружит фактическую необходимость; ожидаемый дизайн этого не требует.

## Совместимость

Сохраняются:

- добавление, удаление и перемещение запчастей;
- выделение запчасти;
- работа нескольких экземпляров одного типа;
- все существующие виды полей и вложенные списки;
- состояние dirty/save и ручное сохранение;
- формат `{ part, props }` без административных ID;
- публичная сборка и отображение запчастей.

Не изменяются API, PostgreSQL, JSDoc-парсер, реестр запчастей, механизм сборки,
публичная тема, автосохранение, история и режимы просмотра.

## Проверка

Техническая проверка ограничена:

1. `git diff --check`;
2. один `yarn vyaz:build`, если окружение готово.

Браузерные и E2E-тесты не запускаются. Пользователь вручную проверяет обычное
отображение, открытие и закрытие формы, переключение между запчастями,
немедленное обновление свойств, вложенные списки, добавление, удаление,
перемещение, сохранение и ширины 375, 768 и 1440 px.

# Универсальное редактирование свойств страницы

## Цель

Использовать один механизм редактирования названия и пути страницы в карте
страниц и в шапке редактора. Изменение реквизитов страницы выполняется без
перезагрузки и независимо от содержимого страницы и статуса его сохранения.

## Общая форма

`components/admin/PageDetailsForm.jsx` получает:

- `page` с `id`, `title` и `path`;
- `onSaved(updatedPage)` для применения ответа сервера;
- `onCancel()` для закрытия формы;
- `onDirtyChange(isDirty)` для владельца представления;
- необязательные классы корневой формы, полей и области действий, позволяющие
  сохранить существующую grid-геометрию `PageList`.

Форма хранит локальные `title`, `path` и статус отправки. Начальные значения
обновляются при смене `page`. Изменение любого поля немедленно пересчитывает
`isDirty` и сообщает его через `onDirtyChange`.

Кнопка сохранения отключена без изменений и во время запроса. Enter отправляет
форму. Escape отменяет редактирование, если запрос не выполняется. Потеря фокуса
ничего не сохраняет. При открытии фокус получает поле пути, а для главной
страницы `/` — поле названия.

Путь главной страницы недоступен для редактирования. Для неё PATCH содержит
только `title`; для остальных страниц — `title` и `path`.

## PATCH и ошибки

Сетевой запрос находится только в `PageDetailsForm`. Он использует существующий
`PATCH /api/pages/:pageId` и возвращаемый сервером объект страницы. Отдельная
API-обёртка не создаётся, поскольку единственным потребителем запроса является
общая форма.

При успешном ответе форма вызывает `onSaved(updatedPage)`. При ошибке она
остаётся открытой и сохраняет введённые значения. Пользователь получает
понятное сообщение:

- `400` — «Проверьте название и путь страницы.»;
- `409` — «Страница с таким путём уже существует.»;
- остальные статусы или сетевая ошибка — «Не удалось изменить страницу.».

Повторная отправка во время запроса заблокирована. Ошибка очищается при новой
попытке сохранения, а не при изменении поля.

## Карта страниц

`PageList` сохраняет текущее inline-представление и CSS Grid. Он владеет только
идентификатором редактируемой строки и признаком изменений, необходимым для
блокировки кнопок «Изменить» других строк.

В редактируемой строке вместо локальной формы рендерится `PageDetailsForm` с
существующими классами `rowContents`, `path`, `title` и `actions`. Успешное
сохранение передаётся владельцу списка и закрывает строку; отмена также закрывает
её и возвращает фокус кнопке «Изменить». Ошибка оставляет строку открытой.

`PagesPage` больше не выполняет PATCH. Его callback только заменяет title/path
полученной страницы в локальном массиве, после чего существующая сортировка
перестраивает список. Создание, удаление и корзина не изменяются.

## Шапка редактора

Существующая кнопка карандаша в `AdminHeader` становится активной после
успешной загрузки страницы. Она открывает компактный `PageDetailsDialog`,
содержащий тот же `PageDetailsForm`.

Диалог реализуется нативным `<dialog>` и открывается через `showModal()` после
рендера. Escape и кнопка «Отмена» закрывают его без сохранения; после закрытия
фокус возвращается кнопке карандаша. Отправка формы и отображение ошибок
остаются ответственностью `PageDetailsForm`.

После успешного PATCH диалог вызывает callback через `AdminShell` в
`Editor.jsx`. `Editor` обновляет только объект `page` значениями из ответа
сервера. Диалог закрывается, а новое название сразу появляется в шапке.

## Независимость содержимого

Обновление реквизитов не вызывает `markDirty`, не изменяет `content`,
`revision`, `isDirty`, `saveStatus` или `editingPartId`. Несохранённые изменения
запчастей остаются в памяти, а кнопка сохранения содержимого сохраняет прежнее
состояние и поведение.

Маршрут редактора содержит стабильный `pageId`, поэтому изменение публичного
пути не требует изменения административного URL или перезагрузки страницы.

## Стили и доступность

`PageDetailsForm` и `PageDetailsDialog` используют CSS Modules и существующие
административные токены, `Button` и `Icon`. Диалог имеет доступное название,
ошибка выводится с `role="alert"`, а кнопки сохраняют `title` и доступные имена.

Стили карты страниц, размеры строк и мобильная сетка не меняются. Диалог
ограничивает ширину формы, но на узком экране занимает доступную ширину без
горизонтальной прокрутки.

## Границы

Не изменяются серверный API, PostgreSQL, маршруты, формат страницы, публичный
рендеринг, операции над запчастями и механизм сохранения содержимого. Новые
зависимости, универсальный конструктор форм и второй независимый PATCH-механизм
не добавляются.

## Проверка

Техническая проверка ограничена:

1. `git diff --check`;
2. `yarn vyaz:build`.

Пользователь вручную проверяет inline-редактирование, диалог шапки, ошибки 400 и
409, запрет пути `/`, Escape, возврат фокуса и сохранность несохранённых
изменений запчастей.

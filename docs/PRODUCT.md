# Kroy: продукт и границы MVP

**Статус документа:** принятые продуктовые решения. Это описание целевой версии, а не перечень уже реализованных возможностей. Текущее состояние — в [README](../README.md) и [EDITOR](EDITOR.md).

## Назначение

Kroy — единая мультисайтовая платформа для разработки и обслуживания небольших клиентских сайтов. Сайты собираются из переиспользуемых React-компонентов — **запчастей**. Инструмент предназначен прежде всего для работы администратора платформы и владельцев сайтов, а не для самостоятельной произвольной разработки пользователем.

На первом этапе поддерживается **только мультисайтовая платформа**. Отдельный режим `single-site` не нужен: инсталляция с одним сайтом остаётся обычной инсталляцией платформы.

## Роли и возможности

В MVP достаточно двух уровней доступа:

| | Администратор платформы | Владелец сайта |
|---|---|---|
| Создание и настройка сайтов | Да | Нет |
| Структура страниц и набор запчастей | Да | Нет |
| Макеты, темы и основные настройки оформления | Да | Нет |
| Назначение пользователей на сайты | Да | Нет |
| Редактирование содержимого запчастей (текстов, изображений и др. разрешённых `props`) | Да | Да, в пределах своего сайта |
| Модерация отзывов своего сайта | Да | Да |

Точные названия ролей, таблицы прав и механизмы авторизации пока не спроектированы. Запчасть сама определяет через JSDoc, какие свойства доступны в редакторе; разделение прав применяется на уровне приложения.

В будущем владелец сможет получить больше контроля над собственным сайтом, но **самостоятельное изменение структуры в MVP не входит**.

## Работа со страницей

- Администратор собирает страницу из запчастей, меняет их порядок и настраивает структуру.
- Владелец редактирует разрешённое содержимое своей страницы, не изменяя состав запчастей.
- Одна страница хранится одним упорядоченным документом с `part` и `props`. Технические `id` редактора не публикуются и не сохраняются.
- Сохранение и публикация изменений предполагаются единым атомарным действием.
- Отдельных черновиков, согласования публикаций и режима предпросмотра *опубликованной версии* в MVP нет. Локальный живой предпросмотр во время редактирования — другая функция, он уже есть в прототипе.

## Отзывы

Для клиентских сайтов предусмотрены отправка посетителем отзыва и модерация владельцем. Отзывы — **отдельные записи в БД**, а не часть JSON страницы. Предполагаемые состояния: `pending`, `published`, `rejected`. Нужна базовая защита от спама; конкретные механизмы и HTTP-контракт ещё не утверждены.

## Не входит в MVP

- Автономный экспорт одного сайта в архив, контейнер или отдельный проект для самостоятельного размещения.
- Отдельный режим запуска платформы «один сайт».
- Полный визуальный CSS-редактор или произвольный редактор кода для владельца.
- Черновики, история версий и сложные процессы согласования.

Экспорт отдельного сайта (с кодом, нужными запчастями, данными, медиа и необходимыми сервисами) — отдельная возможная задача **после** мультисайтового MVP.

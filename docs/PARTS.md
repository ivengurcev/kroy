# Запчасти, виджеты и метаданные

Технический справочник текущего контракта. Обязательные ограничения —
[arch-rules.md](arch-rules.md), общая схема — [architecture.md](architecture.md).

## Данные и отображение

Запчасть — обычная синхронная функция без JSX:

```js
prepare({ props, record, context, contacts, catalog, reviews, materials, materialSectionId }) -> data
```

`props` — настройки данных блока, `record` — текущая запись детальной страницы,
`context.params` — параметры маршрута; остальные поля — общие источники сайта
или section-scoped данные списка материалов. Подготовка, фильтрация, подбор и нормализация выполняются
запчастью. Источники и record не записываются в content.

Виджет — React-компонент с аргументами `{ data, options, context }`.
`data` — результат запчасти, `options` — `view.props`. Виджет отображает готовые
данные; загрузка checkout или отправка формы могут выполняться его интерактивными
компонентами, но не заменяют подготовку содержимого блока.

Сохраняемый блок имеет ровно три поля:

```json
{
  "part": "@kroy/reviews",
  "props": { "mode": "auto", "limit": 5 },
  "view": { "name": "@kroy/review-cards", "props": { "columns": 3 } }
}
```

`view` имеет ровно `name` и `props` и обязателен. `shared/pageContent.mjs` проверяет
объекты, известные имена и точное совпадение непустого контракта. Проверку
используют API сохранения и генератор реестра сайта. При сборке допускается
отсутствующая запчасть: она и её виджет не импортируются, в консоль выводится
предупреждение, а общий Page отображает заглушку с именем запчасти. Остальные
блоки продолжают собираться. API сохранения по-прежнему требует известные имена.
Ошибки структуры блока и несовместимые виджеты существующих запчастей остаются
ошибками сборки. Старый формат без `view`
не поддерживается runtime. Временный id редактора исключается при сохранении.

## Регистрация

`build/registry/discoverParts.mjs` рекурсивно обходит `site/parts/` и
`site/widgets/`. Команда `bun run parts:generate` запускает её через CLI-обёртку
`scripts/discoverParts.mjs`. Алгоритм discovery:

- Каталог с `package.json` регистрирует одну точку входа `main`; внутрь него
  дальнейший поиск не идёт. `main` не может выходить за пределы каталога.
- Каталог без package.json — контейнер для вложенных каталогов.
- Отдельные `.jsx` или `.mjs` без package.json не регистрируются.
- Явное `name` имеет приоритет; иначе имя выводится из пути с нормализацией сегментов.
  Формат — `@kroy/<kebab-case>`, допускаются вложенные сегменты. Проверяются коллизии,
  формат имён и существование файла. Специальный Workspace или базовый класс не нужен.

Например, `site/parts/services/package.json` указывает на `prepareServices.mjs`,
`site/widgets/services/package.json` — на `Services.jsx`; оба могут иметь имя
`@kroy/services`, так как принадлежат разным реестрам.

## JSDoc

Единственный источник схемы — JSDoc непосредственно перед `export default`.
`fields` из package.json не участвует в генерации.

```js
/**
 * @kroy-title Услуги
 * @kroy-category Контент
 * @kroy-contract services
 * @kroy-default-widget @kroy/services
 * @param {object} props
 * @param {string} props.title - Заголовок секции
 * @kroy title widget=textarea
 */
export default function prepareServices({ props }) {
    return { title: props.title };
}
```

У виджета JSDoc объявляет тот же `@kroy-contract` и поля настроек `props.*`, хотя
runtime получает их как `options`. Пример:

```jsx
/**
 * @kroy-title Карточки отзывов
 * @kroy-contract reviews
 * @param {number} [props.columns=3] - Количество колонок
 * @kroy columns widget=number min=1 max=4
 */
export default function ReviewCards({ data, options, context }) {
    // React-разметка по data и options.columns.
}
```

Boolean-настройки виджета отображаются стандартным checkbox в редакторе и задают
значение по умолчанию через `@param {boolean} [props.name=false]`. Для виджета
услуг `defaultExpanded` определяет только начальное состояние разделов; если
свойство отсутствует в сохранённом экземпляре, разделы начинаются свёрнутыми.

Подписи вариантов select задаются через JSDoc отдельно от сохраняемых значений:
`@kroy imageSide optionLabels=left:Слева,right:Справа`. Пары разделяются запятыми,
значение и подпись — двоеточием; подписи не содержат пробелов. Значения перечисления
остаются прежними, редактор показывает соответствующие русские подписи.

Генератор требует у каждой запчасти существующий default widget и точное
совпадение непустых контрактов. Именованный контракт — строка без центрального
перечня значений. При отсутствии title/category используются имя из последнего
сегмента и «Другое». Это не меняет технический идентификатор.

| Тип или настройка | Поле / поведение |
|---|---|
| `string`, `number`, `boolean` | input, number, checkbox |
| `'one'\|'two'` | select |
| `{name: string, link: string}[]` | list с вложенными полями |
| `string[]` | выбор позиций каталога |
| `widget=textarea`, `widget=tel`, `widget=url` | текстовая область или типизированный input |
| `widget=catalog-category`, `widget=review-list` | выбор категории или отзывов |
| `widget=image aspectRatio=4:3 maxWidth=1200` | кадрирование и ограничение ширины изображения |
| `maxLength=30`, `format=ru`, `label=...` | ограничения/формат/подпись |
| `min=1 max=4` | границы числового поля |

Defaults простых значений задаются в необязательном `@param`, например
`[props.columns=3]`. Настройки `@kroy socials.link ...` обращаются к вложенным
полям списка; это не отдельные вложенные `@param props.a.b`.
Для загружаемых иконок используется `widget=image format=media maxWidth=512`
без фиксированного кадрирования. В этом режиме ImageField сохраняет
`{ src, mimeType }` вместо строки URL; MIME возвращается API загрузки.
Кнопка «Убрать иконку» очищает значение без удаления элемента списка.
Общий Image принимает оба формата. При `monochrome` SVG выводится маской
с цветом темы, растр — обычным изображением с исходными цветами.
Старые строковые URL также поддерживаются; прежние имена встроенных иконок
не считаются изображениями и скрываются до загрузки файла. Миграция не нужна.

Растровые изображения, поддерживаемые декодером Sharp (включая JPEG, PNG,
WebP, GIF, AVIF/HEIF и TIFF), обрабатываются сервером в WebP. Без aspectRatio
сохраняются исходные пропорции. `ImageField` отправляет параметры обработки
в API медиа, а props хранит ссылку на результат. Если браузер не умеет открыть
растр для кадрирования, исходный файл обрабатывается сервером без клиентского
кадрирования.

SVG загружается непосредственно, без canvas, кадрирования, изменения размеров
или растеризации; сохраняются исходные байты и формат `.svg` с MIME
`image/svg+xml`. Тип определяется сервером по содержимому, а не имени файла.
Общий лимит сохранённого файла — 10 МиБ. Это правило действует и для изображений
отзывов: SVG отправляется исходным файлом, растровая фотография — через WebP.

Серверный `processImage` возвращает `{ bytes, format }`, где `format` равен
`webp` или `svg`; `storeMedia` выбирает соответствующие расширение и MIME.
SVG выдаётся с `Content-Security-Policy: sandbox` и ограничениями внешних ресурсов,
а также `X-Content-Type-Options: nosniff`. Копии в опубликованном релизе защищены
тем же CSP в генерируемом конфиге Nginx. SVG используется как изображение,
а не вставляется в HTML-разметку сайта.

Парсер отвергает неподдерживаемые типы, неизвестные параметры @kroy и неверные
пути полей. Значение `widget` записывается в схему, но наличие соответствующего
контрола нужно проверять в `admin/editor/Field.jsx`; генератор не гарантирует его.
`required` и validators в метаданных не означают полной серверной проверки props.

## Реестры и стили

`bun run parts:generate` через `build/registry/discoverParts.mjs` создаёт в `dist/kroy/`
полные `parts.mjs`, `parts.json`, `widgets.mjs`, `widgets.json` для редактора.
`build/site/generateSiteParts.mjs`, вызываемый `site:build`, создаёт `site-parts.mjs`
с экспортами parts/widgets только используемых блоков, включая детальные страницы.
SSR и гидратация используют этот общий сокращённый реестр.

`site/runtime/SiteRoot.jsx` применяет scoped CSS-переменные `--site-*` из темы сайта. Виджеты
используют их для палитры, типографики и базовой геометрии, сохраняя свою компоновку
и адаптивность. Тема вычисляется по настройкам конкретного сайта; административная
тема независима. Файлы в dist не редактируются вручную.

## Разделитель и публичные иконки

В «Оформлении сайта» поле «Сепаратор» загружает картинку штатным ImageField
без фиксированного кадрирования. `separatorMediaId` в настройках оформления —
UUID медиа текущего сайта или `null`. Смена темы и сброс её токенов сохраняют
сепаратор. Изображение общее для всех разделителей сайта, независимо от палитры.

`site/components/HR.jsx` получает `{ src, mimeType }` через контекст публичного корня
(`theme.separatorUrl`, `theme.separatorMimeType`). Компонент имеет роль `separator`: картинка находится
между двумя линиями, её максимальная высота — `--site-space-8`, пропорции
сохраняются. Базовая толщина всех линий сайта задаётся токеном `--site-line-width`
(по умолчанию 1px), доступным в «Оформлении → Геометрия», и не зависит от палитры.
Без картинки остаётся пустая полоса высотой `--site-space-12`, без линий
и запасного символа. Размер иконки отдельно не настраивается.
HeroEditorial использует этот компонент вместо линий с ромбом.

Общий `site/components/Image.jsx` принимает `src`, `mimeType`, `monochrome`
(по умолчанию false), `alt` и `className`. Обычные изображения выводятся через
`img` с исходными цветами. Только SVG при `monochrome=true` выводится как
CSS-маска с `background-color: currentColor`, `mask-mode: alpha` и сохранением
пропорций. Такой режим превращает SVG в одноцветный силуэт. Без src компонент
не выводит элемент; неизвестный MIME использует обычный `img`. Alt у маски
превращается в доступное имя, пустой alt означает декоративную картинку.

HR включает `monochrome`, поэтому SVG наследует тот же цвет, что и линии,
а растровый сепаратор сохраняет цвета. Маска занимает квадрат со стороной
`--site-space-8`, SVG вписывается в него целиком. MIME приходит из БД в API
предпросмотра и в данные релиза; компонент не делает дополнительных запросов
и не определяет формат по URL. SVG-файл остаётся неизменным и не вставляется
как inline-разметка. Встроенные иконки по-прежнему обслуживает отдельный `Icon`.

В редакторе доступен отдельный блок `@kroy/separator` с контрактом `separator`
и одноимённым default widget. У него нет собственных данных или настроек:
сохраняется `{ part: '@kroy/separator', props: {}, view: { name: '@kroy/separator', props: {} } }`.
Блок можно добавлять, удалять и переставлять штатными средствами.

В предпросмотре `separatorUrl` ведёт на `/api/media/<id>`. Сборка копирует
изображение в `assets/separator/` релиза, поэтому опубликованный разделитель
не зависит от API медиа и не меняется до следующей публикации. Изменение
сепаратора учитывается при сравнении сохранённых данных с опубликованными.

Публичные виджеты используют `site/components/Icon.jsx`: свойства `name`,
`size` (по умолчанию 24), `className`; неизвестное имя возвращает `null`.
Общий viewBox — 24×24, цвет — `currentColor`, контур —
`--site-line-width-icon` (1.8 × базовая толщина) с округлёнными соединениями.
Набор включает `check`, `star`, `heart`, `leaf`, `book`, `shield`,
`chevron-left`, `chevron-right`, `plus`, `minus`, `telegram`, `instagram`,
`vk`, `youtube`, `tiktok`, `max`, `other` (`link` — то же обозначение ссылки).
Фирменные заполненные знаки сохраняют силуэт. SVG декоративные; доступное имя
задают родительские кнопки/ссылки. Административный Icon остаётся отдельным.

## Толщина линий

Единственный сохраняемый размер штриха — `--site-line-width` (по умолчанию 1px).
`themeRegistry` и базовые стили вычисляют из него `--site-line-width-2`,
`--site-line-width-3`, `--site-line-width-4` и `--site-line-width-icon`
с множителями 2, 3, 4 и 1.8. Обычные границы, подчёркивания и полосы используют базовое значение,
контуры фокуса — двойное, акцентные границы — двойное/тройное, рамка маркера карты —
четверное. Размеры иконок, отступы, скругления и заполненные фирменные знаки
не относятся к толщине штриха. Производные значения не добавляются в overrides
и редактор. Границы элементов Leaflet переопределяются в scoped стилях карты.

## Типографика

В выборе шрифтов редактора доступны локальные Yeseva One, Oswald,
Roboto Condensed и Caveat — по одному пункту на семейство. Насыщенность
не создаёт отдельные пункты: Oswald, Roboto Condensed и Caveat подключены
variable-файлами; для Roboto Condensed доступен также настоящий курсив.
Общие `@font-face` в `site/styles/fonts.css` используются редактором и
публичной темой. TTF берутся из `site/assets/fonts/`, копируются сборщиком
в ресурсы приложения/релиза и не требуют внешних запросов к Google Fonts.
Статические дубликаты начертаний удалены; лицензии OFL сохранены рядом с файлами.

Публичные размеры текста берутся из `--site-font-size-*`, определённых в
`site/styles/SiteTheme.module.css`. Каждый размер равен
`calc(var(--site-font-size-base) * коэффициент)`; базовое значение по-прежнему
настраивается через общие theme overrides. Производные размеры не сохраняются
и не становятся отдельными полями редактора. В `themeRegistry` сохраняется
прежняя обработка базового размера, без второго набора формул.

Шкала адаптируется ступенчато по ближайшему inline-size контейнеру:
мобильные коэффициенты до 768 px, промежуточные от 768 px,
десктопные от 1200 px. Определение токенов на потомках публичной темы
обеспечивает пересчёт в узких карточках; корень сайта, карточки, диалог отзывов
и материал предоставляют соответствующие контейнеры. Это сохраняет точное
пропорциональное масштабирование при любой базе, без независимого слагаемого `vw`.

| Роль / суффикс токена | <768 px | 768–1199 px | ≥1200 px | При базе 16 px, мобильный / десктоп |
|---|---:|---:|---:|---:|
| Small / `small` | .875 | .875 | .875 | 14 / 14 |
| Body / `body` | 1 | 1 | 1 | 16 / 16 |
| Lead / `lead` | 1.125 | 1.1875 | 1.25 | 18 / 20 |
| H6 / `h6` | 1 | 1.0625 | 1.125 | 16 / 18 |
| H5 / `h5` | 1.125 | 1.1875 | 1.25 | 18 / 20 |
| H4 / `h4` | 1.25 | 1.375 | 1.5 | 20 / 24 |
| H3 / `h3` | 1.5 | 1.625 | 1.75 | 24 / 28 |
| H2 / `h2` | 1.75 | 2 | 2.25 | 28 / 36 |
| H1 / `h1` | 2.25 | 2.625 | 3 | 36 / 48 |
| Display / `display` | 2.75 | 3.375 | 4 | 44 / 64 |

Например, при базе 18 px H1 равен 40.5 / 54 px, Display — 49.5 / 72 px;
при базе 20 px H1 равен 45 / 60 px, Display — 55 / 80 px.
Small / Body при этих базах равны 15.75 / 18 px и 17.5 / 20 px соответственно.

Обычный Hero использует H1, журнальный Hero — Display. Заголовки секций
используют H2, названия карточек — H4/H5. Семантика HTML независима от визуальной
роли. Высота строк текста следует `--site-line-height` (по умолчанию 1.5),
заголовков — 1.2, Display — 1.05. Семейства, палитры и контент не меняются.
Декоративные SVG, знаки управления и пиктограммы сохраняют собственные размеры.

## Первый экран: Hero

Запчасть `@kroy/hero` и оба её виджета используют контракт `hero`.
Виджет по умолчанию — `@kroy/hero`; дополнительный `@kroy/hero-editorial`
(«Первый экран — журнальный») выбирается штатным списком отображений редактора.

Содержимое хранится в `part.props`: прежние `eyebrow`, `title`, `photo`,
`captionTitle`, `description` и необязательные `subtitle`, `lead`, `features`,
`topNote`, `bottomNote`. `features` — упорядоченный список `{ icon, text }`,
где `icon` — загружаемое изображение `{ src, mimeType }` (или строковый URL).
Пустые тезисы и отсутствующие иконки не оставляют пустых элементов или кругов. Социальные ссылки по-прежнему поступают из контактов сайта.

Журнальный виджет объединяет `title` и `subtitle` в один `h1`, использует
`captionTitle` и `description` для нижней плашки. Пустые необязательные элементы
не выводятся. Настройка `view.props.photoPosition` (`left`, `center`, `right`,
по умолчанию `center`) управляет горизонтальным положением фотографии;
изображение заполняет область с кадрированием без искажения пропорций.
Загрузка фото сохраняет прежнее кадрирование 3:4 и ограничение ширины 1600 px.
Для наложения текста нужна фотография со свободной областью слева:
автоматического определения лица нет. На узких экранах декоративные подписи
располагаются в потоке. Старый Hero не использует новые поля; миграция данных
не требуется.

## Текст: журнальное отображение

Запчасть `@kroy/text` отображается в списке блоков как «Текст» и имеет контракт
`text`, default widget — `@kroy/text` («Текст — обычный»).
Дополнительное отображение `@kroy/text-editorial` называется
«Журнальный — с фотографией». Внешний вид обычного отображения сохраняется.
Прежний тип `@kroy/about` удалён без миграции сохранённых данных: такие блоки
показывают заглушку до замены пользователем на новый тип.

В `part.props` сохраняются прежние `title`, `text` и необязательные `lead`,
`photo`, `photoAlt`. Разбиение `text` на абзацы по пустым строкам прежнее;
`lead` — отдельный вводный абзац. `photo` редактируется штатным ImageField
без принудительного соотношения сторон, с ограничением ширины 1600 px.
`photoAlt` передаётся в обычный `img` через общий Image без monochrome-режима.

Настройки `view.props`: `imageSide` (`left`/`right`, по умолчанию `right`)
и `imagePosition` (`left`/`center`/`right`, по умолчанию `center`). Первая
настройка действует на широких контейнерах от 900 px, вторая задаёт
горизонтальный `object-position` при `object-fit: cover`.

На узком экране идут заголовок, фотография, вводный и основной текст.
На широком фотография располагается рядом с текстом, фон темы плавно
переходит в изображение. Высота определяется содержимым, без привязки к экрану.
Без фотографии остаётся один текстовый столбец; пустые поля не создают
контейнеров. Заголовок остаётся `h2`, визуальный размер — Display; вводный
абзац использует Lead, основной текст — Body. Цвета и шрифты берутся из темы.
Смена отображения сохраняет общие данные, миграция БД не нужна.

## Карточки

Запчасть `@kroy/cards` («Карточки») готовит статический контент с контрактом
`cards`. Её default widget — `@kroy/feature-cards` («Карточки с иконками»).
Содержимое хранится в обычном `pages.content`, независимо от каталога,
услуг и материалов; миграции БД не нужны.

Настройки данных: необязательные `title`, `headingIcon`
и список `cards` из `{ icon, title, description }`. Штатный ListField добавляет,
удаляет и переставляет элементы; название и описание редактируются как textarea.
Текст очищается от пробелов по краям; полностью пустые карточки не выводятся.
Количество карточек не ограничено. Иконки заголовка и карточек загружаются
штатным ImageField и хранятся как `{ src, mimeType }`. Если изображения нет,
круг отсутствует. SVG наследует цвет темы через маску общего Image,
растр сохраняет исходные цвета; все изображения вписываются без обрезки.

Единственная настройка `view.props` — `columns`, число от 1 до 4,
по умолчанию 4. До 375 px ширины контейнера используется одна колонка,
от 375 px — до двух, от 1024 px — выбранное число. При `columns: 1`
сетка всегда одноколоночная. Карточки в одном ряду растягиваются по высоте
самой высокой; длинный текст переносится и не обрезается.

Виджет использует Section, семантический список, `h2` для секции и `h3`
для карточек. Размеры текста — H2, H4 и Body общей шкалы. Фон карточек,
круги иконок, шрифты, интервалы и радиусы определяются темой; карточки
не интерактивны. Пустые заголовки, описания и сетка не создают пустых элементов.

## Миграция старых документов

Разовый скрипт обрабатывает все страницы, включая корзину; добавляет отсутствующий
view по default widget и сохраняет уже выбранные совместимые view/props.
Неизвестная запчасть или несовместимый виджет останавливает операцию без записи.
Dry-run по умолчанию:

```bash
bun scripts/migratePageViews.mjs
```

После проверки результата и явного разрешения на изменение рабочей БД:

```bash
bun scripts/migratePageViews.mjs --apply
```

Запись — одна транзакция с блокировкой строк. Повторный запуск не меняет уже
мигрированные страницы. Скрипт не входит в db:migrate и не запускается сборкой
или публикацией. Во время применения и переключения runtime не должно быть
записей старой версией редактора. В development выполнять внутри app через
`docker compose -f infra/compose.yaml exec app`.

Переименование идентификатора требует отдельного обновления сохранённых
документов. Автоматической системы миграций props и переименований нет.

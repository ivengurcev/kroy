# Запчасти, виджеты и метаданные

Технический справочник текущего контракта. Обязательные ограничения —
[arch-rules.md](arch-rules.md), общая схема — [architecture.md](architecture.md).

## Данные и отображение

Запчасть — обычная синхронная функция без JSX:

```js
prepare({ props, record, context, contacts, catalog, reviews, articles }) -> data
```

`props` — настройки данных блока, `record` — текущая запись детальной страницы,
`context.params` — параметры маршрута; остальные поля — общие источники сайта
или данные списка статей. Подготовка, фильтрация, подбор и нормализация выполняются
запчастью. Источники и record не записываются в content.

Виджет — React-компонент с аргументами `{ data, options, context }`.
`data` — результат запчасти, `options` — `view.props`. Виджет отображает готовые
данные; загрузка checkout или отправка формы могут выполняться его интерактивными
компонентами, но не заменяют подготовку содержимого блока.

Сохраняемый блок имеет ровно три поля:

```json
{
  "part": "@kroy/reviews",
  "props": { "mode": "auto", "limit": 5 },
  "view": { "name": "@kroy/review-cards", "props": { "columns": 3 } }
}
```

`view` имеет ровно `name` и `props` и обязателен. `api/pageContent.mjs` проверяет
объекты, известные имена и точное совпадение непустого контракта. Проверку
используют API сохранения и генератор реестра сайта. Старый формат без `view`
не поддерживается runtime. Временный id редактора исключается при сохранении.

## Регистрация

`scripts/discoverParts.mjs` рекурсивно обходит `parts/` и `widgets/`:

- Каталог с `package.json` регистрирует одну точку входа `main`; внутрь него
  дальнейший поиск не идёт. `main` не может выходить за пределы каталога.
- Каталог без package.json — контейнер для вложенных каталогов.
- Отдельные `.jsx` или `.mjs` без package.json не регистрируются.
- Явное `name` имеет приоритет; иначе имя выводится из пути с нормализацией сегментов.
  Формат — `@kroy/<kebab-case>`, допускаются вложенные сегменты. Проверяются коллизии,
  формат имён и существование файла. Специальный Workspace или базовый класс не нужен.

Например, `parts/services/package.json` указывает на `prepareServices.mjs`,
`widgets/services/package.json` — на `Services.jsx`; оба могут иметь имя
`@kroy/services`, так как принадлежат разным реестрам.

## JSDoc

Единственный источник схемы — JSDoc непосредственно перед `export default`.
`fields` из package.json не участвует в генерации.

```js
/**
 * @kroy-title Услуги
 * @kroy-category Контент
 * @kroy-contract services
 * @kroy-default-widget @kroy/services
 * @param {object} props
 * @param {string} props.title - Заголовок секции
 * @kroy title widget=textarea
 */
export default function prepareServices({ props }) {
    return { title: props.title };
}
```

У виджета JSDoc объявляет тот же `@kroy-contract` и поля настроек `props.*`, хотя
runtime получает их как `options`. Пример:

```jsx
/**
 * @kroy-title Карточки отзывов
 * @kroy-contract reviews
 * @param {number} [props.columns=3] - Количество колонок
 * @kroy columns widget=number min=1 max=4
 */
export default function ReviewCards({ data, options, context }) {
    // React-разметка по data и options.columns.
}
```

Генератор требует у каждой запчасти существующий default widget и точное
совпадение непустых контрактов. Именованный контракт — строка без центрального
перечня значений. При отсутствии title/category используются имя из последнего
сегмента и «Другое». Это не меняет технический идентификатор.

| Тип или настройка | Поле / поведение |
|---|---|
| `string`, `number`, `boolean` | input, number, checkbox |
| `'one'\|'two'` | select |
| `{name: string, link: string}[]` | list с вложенными полями |
| `string[]` | выбор позиций каталога |
| `widget=textarea`, `widget=tel`, `widget=url` | текстовая область или типизированный input |
| `widget=catalog-category`, `widget=review-list` | выбор категории или отзывов |
| `widget=image aspectRatio=4:3 maxWidth=1200` | кадрирование и ограничение ширины изображения |
| `maxLength=30`, `format=ru`, `label=...` | ограничения/формат/подпись |
| `min=1 max=4` | границы числового поля |

Defaults простых значений задаются в необязательном `@param`, например
`[props.columns=3]`. Настройки `@kroy socials.link ...` обращаются к вложенным
полям списка; это не отдельные вложенные `@param props.a.b`.
Изображения JPEG/PNG/WebP обрабатываются сервером в WebP. Без aspectRatio
сохраняются исходные пропорции. `ImageField` отправляет параметры обработки
в API медиа, а props хранит ссылку на результат.

Парсер отвергает неподдерживаемые типы, неизвестные параметры @kroy и неверные
пути полей. Значение `widget` записывается в схему, но наличие соответствующего
контрола нужно проверять в `admin/editor/Field.jsx`; генератор не гарантирует его.
`required` и validators в метаданных не означают полной серверной проверки props.

## Реестры и стили

`yarn parts:generate` создаёт в `dist/kroy/` полные `parts.mjs`, `parts.json`,
`widgets.mjs`, `widgets.json` для редактора. `site:build` создаёт `site-parts.mjs`
с экспортами parts/widgets только используемых блоков, включая детальные страницы.
SSR и гидратация используют этот общий сокращённый реестр.

`SiteRoot` применяет scoped CSS-переменные `--site-*` из темы сайта. Виджеты
используют их для палитры, типографики и базовой геометрии, сохраняя свою компоновку
и адаптивность. Тема вычисляется по настройкам конкретного сайта; административная
тема независима. Файлы в dist не редактируются вручную.

## Миграция старых документов

Разовый скрипт обрабатывает все страницы, включая корзину; добавляет отсутствующий
view по default widget и сохраняет уже выбранные совместимые view/props.
Неизвестная запчасть или несовместимый виджет останавливает операцию без записи.
Dry-run по умолчанию:

```bash
yarn node --env-file-if-exists=.env scripts/migratePageViews.mjs
```

После проверки результата и явного разрешения на изменение рабочей БД:

```bash
yarn node --env-file-if-exists=.env scripts/migratePageViews.mjs --apply
```

Запись — одна транзакция с блокировкой строк. Повторный запуск не меняет уже
мигрированные страницы. Скрипт не входит в db:migrate и не запускается сборкой
или публикацией. Во время применения и переключения runtime не должно быть
записей старой версией редактора. В development выполнять внутри app через
`docker compose -f infra/compose.yaml exec app`.

Переименование идентификатора требует отдельного обновления сохранённых
документов. Автоматической системы миграций props и переименований нет.
